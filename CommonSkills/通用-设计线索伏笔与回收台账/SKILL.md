# 通用-设计线索伏笔与回收台账

线索与伏笔不是装饰品，而是作者侧的追读承诺管理系统。

## 风格/蓝本/写作研究模板自动发现规则

若当前服务的项目根目录存在 `Agents.md`，设计或维护线索伏笔台账前必须：

1. 读取项目根目录的 `Agents.md`；若其中声明了 `主输出平台`，检索三类模板时优先匹配"适用平台"与主输出平台一致的模板，无匹配时回退到"适用平台：默认"的同类模板
2. 若 `Agents.md` 中注册了"写作研究模板"——读取对应路径的模板文件，将其信息密度、伏笔公平性、回收要求和平台禁忌作为默认约束基线
3. 若 `Agents.md` 中注册了"作者风格模板"——读取对应路径的模板文件，将其作为伏笔呈现方式、叙事距离、物件细节与禁忌清单参照
4. 若 `Agents.md` 中注册了"作品蓝本模板"——读取对应路径的模板文件，将设悬念、埋线索、部分揭示、完全揭示的节拍作为回收计划参照
5. 本 Skill 只消费与线索 / 伏笔 / 回收相关的字段；若模板字段与推理公平性冲突，公平性和可证伪性优先
6. 若项目根目录不存在 `Agents.md`，或其中未注册对应模板——回退通用默认模式，不报错，不阻断

本 Skill 默认消费字段：

- 写作研究模板：信息密度、伏笔公平性、回收要求、读者耐心阈值、禁忌类约束
- 作者风格模板：叙事距离、感官偏好、比喻指纹、禁忌清单
- 作品蓝本模板：信息释放节拍、章末钩子指纹、中段回报指纹、场景节奏分布

## 常见触发词 / 用户说法速查

- 帮我做线索台账
- 这批伏笔怎么记账
- 看看回收窗口有没有问题
- 这条误导是不是不可证伪
- 帮我整理伏笔和回收计划

## 何时使用

- 新建或重写线索台账、伏笔台账、回收总表。
- 审计现有台账是否存在“编号混乱、字段缺失、回收无代价”的问题。
- 需要把总纲、分卷、章节中的线索与回收动作对齐到统一账本。

## 默认执行顺序

1. 先判本轮对象属于线索台账、伏笔台账还是混合台账。
2. 再按字段模板建立编号、来源、状态、窗口、兑现后果。
3. 再补“提出 → 强化 → 回收 → 余波”的阶段链。
4. 最后检查能否直接回指到总纲、分卷与章级动作。

## 悬念管理与钩子链节律补强（新增）

- 线索台账不只记“埋了什么”，还要记“它属于哪类悬念 / 钩子链的哪一环、上次推进在哪一章、预期何时回应”。
- 默认尽量遵循“每章回应一个旧问题，再打开一个新问题”；若某条线连续多章只被提起不被推进，应标为失温或超期。
- 悬念窗口默认可分：小悬念 `1–3` 章、中悬念 `5–8` 章、大悬念跨卷 / 全书；超窗时要么补推进，要么写明合理延迟原因。
- 同时活跃的高关注悬念线最好控制在 `3–4` 条；超过时，台账里应明确主次与轮换顺序。
- 回收方式默认至少标记一种：对称场景、重复对白、物件回归、信息重组；若最终解答主要依赖末章新信息，默认判为不公平。
- 需警惕并显式标红：虚假悬念、机械降神、过度留白、低风险钩子、同类型钩子连续重复。

## 默认输出口径

- 默认输出一份可直接回指、可跨卷追踪的线索 / 伏笔台账。
- 默认同时补齐编号、状态、窗口与兑现后果。

## 最低交付

- 每条线索/伏笔都有唯一编号与当前状态。
- 每条回收都写清回收窗口、证据载体或触发动作。
- 每条兑现都写清“爽点 / 代价 / 余波”三项中的至少两项。

## 伏笔必回收原则（强制）

> **来源**：自知乎精华《如何写好一个优质的长篇小说？》（摘星，2026-06-17）。

伏笔的核心原则只有一句话：**埋多少，收多少。**

这不是"尽量收"而是"必须收"——每一个被显式埋入正文的伏笔（无论短线、中线、长线），都必须对应一个明确的回收动作。不能回收的伏笔，就不要埋。

### 伏笔分类回收时限

| 伏笔类型 | 最长容忍窗口 | 回收强度要求 | 超期处理 |
| --- | --- | --- | --- |
| **短线伏笔**（章节级） | 3-7章 | 在回收窗口内给出明确的揭示或兑现；不需要"大反转"，但读者需要知道"那个信号被回应了" | 超出7章未回收→标记为失联伏笔，在下一卷的回收计划中安排优先处理 |
| **中线伏笔**（卷级） | 1-2卷 | 在跨1-2卷的篇幅内完成揭示；需要至少一次"强化"（在正式回收前再提一次让读者记住） | 超出2卷未回收→标记为高风险失联，必须在卷级复盘会上决策是回收还是删除 |
| **长线伏笔**（全书级） | 终局前1卷 | 终局前必须完成回收，且回收方式需让读者产生"原来这里早有伏笔"的后知后觉感 | 终局完成后仍未回收→标记为未兑现伏笔，在完本清单中决策是否追加回收章节 |

### 伏笔回收的验收规则

- **短线伏笔**：不得依赖读者记性——如果一段伏笔埋下后超过5章读者已经很难回想起，要么在回收前加一次"回顾提示"，要么当初就不该埋。
- **中线伏笔**：回收时的信息增量必须大于埋设时的信息量。如果"揭秘"只是简单重复已经暗示过的内容（"原来他就是那个黑衣人"而读者早就猜到了），判为回收质量不合格。
- **长线伏笔**：回收时的"后知后觉感"必须来自"线索一直摆在读者面前但解读方向被巧妙引导"，而非"信息从未出现，最后一章硬塞答案"。

## 硬规则

- 禁止只有“这里埋个伏笔”，没有回收窗口。
- 禁止只有“后面回收”，没有回收动作与兑现后果。
- 禁止把误导写成无法证伪的作者遮羞布。
- 禁止同一编号跨文件漂移却没有同步口径。
- 百万字以上项目必须显式区分短线、中线、长线伏笔，并写明强化窗口。
- 终局级谜底不得主要依赖末章首次出现的新信息；关键信号应可回溯到前文。

## 与其他 Skill / Prompt 的边界

- 本 Skill 负责线索、伏笔与回收账本本体。
- 不直接代替总纲、分卷或案件引擎设计。
