# 今日头条版 POV 选择指南

> 若执行本 Skill 时未获得上游明确的 `platformPovContract` 锁定，按以下指南为本平台适配稿确定人称（最终以 `Agents.md` 的 `## 平台POV基线表` 节锁定值为准）。

## 强制前置步骤

必须首先读取工作区根目录 `Agents.md` 的 `## 平台POV基线表` 节，查找本平台的当前锁定人称。若基线表中无本平台条目，必须先在该表中创建条目并锁定人称（参考下方"适用场景分析"），再继续执行。

**人称是全书级契约**：基线表锁定值即为本平台全书的唯一人称，不得逐章切换，不得章内混用（对话引用除外）。极特殊情况下某章须切换主视角人物时，该章开头必须明确声明「我是[角色名]」，且整章只保持该角色的第一人称叙事。

## 今日头条版的人称适用场景（供创建/修订基线表条目时参考）

**平台底层逻辑**：今日头条是"信息流分发 + 深度图文长生命"的混合体。章节以单篇文章形态进入推荐流，开篇 3000 字权重约占 45%。核心读者是 25-40 岁社会中坚，平台同时吃"开篇钩子 + 评论讨论 + 深度图文长生命"。这是唯一一个"推荐标题可以借'我'抓点，但正文不必用'我'叙"的平台。

### 为什么头条偏第三人称？

- 头条的核心互动指标是"评论 + 分享 + 收藏"。第三人称的多角色冲突、可讨论话题与连续反转，天然比第一人称的个人体验更能激发评论——读者评论的是"某某角色的选择对不对"，而非仅仅"我感到害怕"。
- 头条的"一章三钩"策略（章首钩/章中钩/章尾钩）需要快速在不同信息层次间切换。第三人称可以在同一章内呈现"主角看到的线索 + 反派暗中的动作 + 第三方势力的偶然介入"，信息密度最高。
- 研究指出"允许推荐标题借'我'做抓点（如'我在地下室发现了前房主留下的 37 封信'），但正文走'限制性第三人称 + 主角感知锚点'"——头条标题在推荐流中独立展示，可以标题用"我"抓点击、正文用深第三保深度。

### 什么时候头条应用第一人称？

- 故事的核心卖点是"主角的认知偏差/心理误导/主观反转"——读者需要被"我"的主观判断牵着走，然后和"我"一起被反转打脸。这种效果第三人称做不到同等强度。
- **警告**：若全改"我"叙，容易把系统/群像/流程压力压扁成个人爆料，反而削弱"到底哪一层出了问题"的讨论空间。头条读者要的是"可复盘 + 可讨论"，不是单纯的"可怕"。
