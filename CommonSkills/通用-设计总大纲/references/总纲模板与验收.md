## 1.6 ★ 核心张力声明（强制）

> 超长篇靠的是撕裂，不是输赢。核心张力不是主线矛盾（"主角要打败反派"），而是让主角在推进过程中被撕开的那个东西。

| 有撕裂而非只有输赢 | 核心张力涉及"主角必须在两种都对的/都错的选择之间撕裂" | 待填 |
| 有具体代价 | 张力压在一个特定人物身上，有明确的可感知代价 | 待填 |

| 不可替换 | 把世界观/背景换掉后，张力不再成立——说明它长在这个故事里 | 待填 |

## 13. 验收清单

### 叙事层（新增—优先检查）

- [ ] **"一句话讲故事"已写清**：用 100-200 字自然语言把整个故事讲了一遍，未接触过本项目的人能复述
- [ ] **核心张力声明已通过四项检查**：有撕裂而非输赢、有具体代价、能撑住体量、不可替换
- [ ] **终局画面已钉死**：最终场面、读者感受、倒推前提三者齐全
- [ ] **读完总纲后能回答"这是一个关于____的故事"**，而非只能说"这是一部____题材的小说"

### 结构层

- [ ] 已声明主模板 / 辅助模板 / 是否触发默认九线回退
- [ ] 已说明各模板分别负责什么结构职责
- [ ] 已把模板要求吸收入总纲主体，而不是只在声明区挂名
- [ ] 已明确总纲包对象与联动文件
- [ ] 已明确 `小说总大纲.md` 的主线职责与 `故事面/` 的支线职责
- [ ] 已写清主支线如何相互交织、相互联系、相互推动
- [ ] 已写明对标竞对、可借鉴强点与我方落后点
- [ ] 已给出 P0/P1/P2 的竞对导向优化动作
- [ ] `M0` 已写清谜面 / 真相 / 代价
- [ ] `X` 面都是具体故事，不是主题口号
- [ ] `故事面/` 没有被写成 `小说总大纲.md` 的摘要副本
- [ ] `C` 矩阵能持续供血主线
- [ ] 已写清跨卷推进与终局闭环
- [ ] 已保留下游分卷拆解接口

## 14. 三层验收映射（新增）

- `边界验收层`：总纲主文件与 `故事面/` 是否职责清楚、交接清楚。
- `战略验收层`：卖点、竞对超越路线、`M0 / X / C`、跨卷推进、终局闭环是否站得住。
- `维护验收层`：模板组合声明、下游接口、章节规划入口、节奏 / 决策维护口是否齐。

## 15. Green / Yellow / Red 模板验收判定（新增）

- `Green`：三层都过，可作为总纲层标准母版或项目总纲包模板使用。
- `Yellow`：主干完整，但仍缺一层维护或交接细节，适合继续补强后再下压。
- `Red`：模板能看但不能稳用，边界、战略或维护层至少一层明显缺失。
