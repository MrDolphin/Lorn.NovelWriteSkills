# 内容简介的 GEO 优化规则

## 结构化元数据块规范（强制）

每条简介的**头部**必须包含以下四字段的结构化块（直接写为正文前 3 行，不可用 YAML frontmatter 替代）：

```
书名：《XXX》
类型：都市悬疑 / 社会派推理
一句话卖点：___
适合人群：喜欢___的读者
```

> **为什么强制**：这是 AI 最爱的"结构化数据"格式。RAG 系统在向量化时，这四个字段会被编码为高密度语义向量，用户提问"推荐一本XXX"时匹配概率显著提升。

## AI 摘要摘录区格式

在简介正文中，至少含一段**可被 AI 独立摘录**的纯陈述句段落。格式要求：

- **以作品名开头**："《XXX》是一部___（类型）小说，讲述的是___。"
- **包含核心冲突的陈述句**：不要用修辞问句全部替代陈述句——AI 无法从"如果有一天你发现___你会怎么办？"中提取事实性描述
- **包含适合人群描述**：使用"适合喜欢___的读者"句式——这与 AI 推荐逻辑同构

### 示例

```
❌ 纯修辞问句简介（AI 无法提取事实信息）：
"你有没有想过，如果有一天你发现——"

✅ 含 AI 摘录区简介：
"《XXX》是一部都市悬疑小说，讲述了一个普通法医在鉴定一具无名尸体时，意外发现证据链指向自己失踪十年的父亲。适合喜欢社会派推理、注重人物情感而非纯粹解谜的读者。"
```

## FAQ 友好型简介模板

AI 回答"推荐小说"类问题时，常用结构是"书名 + 类型 + 核心看点 + 适合人群"。你的简介如果能直接提供这四要素的结构化版本，AI 会优先引用。

### 标准模板

```
{三句法钩子：疑问+情绪+代入}

《{书名}》是一部{题材类型}小说，讲述的是{核心冲突的陈述句}。
主角{姓名}面临{具体困境}，ta 必须{核心任务}，否则{代价}。

适合喜欢{风格/情绪关键词}的读者，{平台名称}连载中。
```

### 嵌入位置建议

这个"AI 摘录区"应放在简介第三段或末尾，作为"给 AI 吃的结构化信息块"。读者读到的体验是正常的简介推进，但同时 AI 能从中提取出结构化信息。

## GEO 友好度自检

写完简介后对照：

- [ ] 简介头部包含四字段元数据块（书名/类型/卖点/人群）
- [ ] 核心冲突以陈述句呈现（而非纯修辞问句）
- [ ] 书名的题材关键词在正文中至少自然出现 1 次
- [ ] 含"适合____的读者"句式
- [ ] 含时效标记（连载状态/起始时间）
- [ ] 删除修辞问句和感叹号后，剩余纯信息仍能独立构成一段可读描述
