# 通用-撰写内容简介

内容简介不是大纲摘要，而是用最短篇幅把"为什么值得点开继续看"讲清楚。

## 简介即开篇：简介与开头的同构原则（新增）

> **读者看简介的决策模式，和看开头的决策模式完全一样——只是简介是"点开前"的最后一道关卡。**

简介和开头的底层逻辑是**同构**的：

| 维度 | 开头 | 简介 |
|------|------|------|
| 核心任务 | 在 3–5 秒内抓住读者 | 在 3–5 秒内让读者"点开" |
| 交易本质 | 用字换注意力 | 用更短的字换"点一下"的动作 |
| 认知缺口 | 制造"不往下看就亏了" | 制造"不点开就亏了" |
| 卖点展示 | 让读者感知本章核心看头 | 让读者感知全书核心看头 |
| 人际关系反常 | 反常的关系最抓人 | 简介中的关系反常同样让读者好奇 |
| 信息差 | 读者不知道的才是钩子 | 简介露出半扇门比全打开更有效 |
| 三句法 | 前三句：疑问+情绪+代入 | 前三句同样要完成疑问+情绪+代入 |
| 切片原则 | 截取高压瞬间而非概括式叙述 | 截取核心冲突场景而非设定堆砌 |

> **核心结论**：一个好的简介 = 好开头的压缩版 + 全书范围的承诺。坏简介最常见的毛病和坏开头完全一样——设定说明化、概括叙述、没有认知缺口。

## 简介的三句法（新增——吸收自知乎开篇精华）

和章首一样，简介也适用"三句法"——前 3 句话之内，必须完成三件事：

| 序号 | 任务 | 解释 | 示例 |
|------|------|------|------|
| 一 | **让读者产生疑问** | 制造认知缺口 | "签完离婚协议那天，她发现自己怀孕了。"——然后呢？ |
| 二 | **让读者产生情绪** | 情感卷入而非理性理解 | "他跪在她面前，不是求她原谅，是求她签另一份文件。"——震惊/好奇 |
| 三 | **让读者产生代入** | 与自身经验或欲望连接 | "如果你发现结婚三年的丈夫，心里一直住着另一个人——你会怎么做？" |

三句话内三件事全中，读者就被"骗"进试读了。

## 简介的切片原则 vs 大纲体（新增——吸收自知乎开篇精华）

简介最忌讳"大纲体"——堆砌世界观名词、设定要点和背景信息，但没有一个具体的、可感知的瞬间：

```
❌ 大纲体简介：
"苏棠是一个被家族联姻束缚的女性，在前夫的冷落和继母的算计中，逐渐成长为独立的商业精英，最终揭开三份合同背后的家族秘密。"

✅ 切片式简介：
"封余寒把离婚协议推到她面前时，苏棠笑了。
她笑了。三年的婚姻，换来三页纸。
她签字的时候没有哭。直到翻到最后一页，看见附件里那份她从未见过的合同——签字人，是她父亲。
日期，是她结婚前六个月。"
```

切片式简介的核心原则和开头完全一致：**截取故事中最高压、最反常、最戏剧化的一个瞬间，直接怼到读者脸上。** 其他的背景信息，等读者已经被钩住了再慢慢知道。

## 信息差与认知缺口在简介中的应用（新增）

简介不需要把故事的前因后果讲清楚。相反，维持适度的信息不对称——让读者知道"有事发生了、主角陷入了一个局"，但不知道"这个局的真相是什么、代价有多大、结局会怎样"——反而能创造出最强的点开冲动。

简介的信息差公式：
```
读者看到的：主角正在遭遇一个反常的处境
读者不知道的：这个处境的真正原因、幕后推手、真实代价
读者想通过点开知道的：接下来会怎样？谁干的？为什么？
```

> **警告**：信息差不是"故意写不明白"。读者必须知道"主角在经历什么压力"，只是不知道"来龙去脉"。

## 简介的交易本质自检（新增——吸收自知乎开篇精华）

写完简介后，问自己：**"如果读者在这里划走，ta 损失了什么？"**

- 如果答案是"什么都没有"或"一段背景说明"——简介没有完成交易。
- 如果答案是"ta 会错过一个想知道答案的问题"——简介合格。
- 如果答案是"ta 会错过一个放不下的场景/人物/关系"——简介优秀。

> **每句话都应当有价值。不能让读者免费读到任何一句"不重要的"。**

## 风格/蓝本/写作研究模板自动发现规则

若当前服务的项目根目录存在 `Agents.md`，撰写或审计内容简介前必须：

1. 读取项目根目录的 `Agents.md`；若其中声明了 `主输出平台`，检索三类模板时优先匹配"适用平台"与主输出平台一致的模板，无匹配时回退到"适用平台：默认"的同类模板
2. **从 `Agents.md` 中提取已注册的平台列表**（通过 `主输出平台` 字段或 `分发平台` / `平台列表` 等显式声明）；后续所有平台相关的简介撰写与输出**只能针对这些已注册的平台**，未注册的平台不得生成平台适配简介版本
3. 若 `Agents.md` 中注册了"写作研究模板"——读取对应路径的模板文件，将其作为平台简介口径、卖点压缩和禁忌基线
4. 若 `Agents.md` 中注册了"作者风格模板"——读取对应路径的模板文件，将其作为简介语言气质的轻约束，不得压过平台清晰度
5. 若 `Agents.md` 中注册了"作品蓝本模板"——读取对应路径的模板文件，将其作为核心结构承诺、主线问题和持续追读承诺参照
6. 本 Skill 只消费与简介撰写相关的字段；若作者风格与平台简介清晰度冲突，平台简介清晰度优先
7. 若项目根目录不存在 `Agents.md`，或其中未注册对应模板——回退通用默认模式，不报错，不阻断

本 Skill 默认消费字段：

- 写作研究模板：平台简介口径、标签热词、卖点压缩、禁忌类约束
- 作者风格模板：整体文风、句长基线、禁忌清单、语言气质
- 作品蓝本模板：整体叙事策略、章首承诺、核心冲突、钩子类型

## 何时使用

- 新书上架前撰写简介。
- 已有简介太像设定说明、太空、太散，需要重写。
- 针对不同平台生成不同长度、不同口气的简介版本。

## 默认执行顺序

1. **检查项目根目录是否存在 `Agents.md`：若存在，读取并提取其中已注册的平台列表；若不存在或未声明任何平台，则只输出不区分平台的通用主版简介，跳过所有平台适配步骤。**
2. 先确认本次简介使用的名称口径：不分部小说使用小说的目标投放名，分部小说使用对应部的目标投放名；再抓主卖点、主角当前困境与不可回头的入局点。
3. 先判断当前简介是"切片式"还是"大纲体"：若当前草稿堆砌世界观名词和设定要点，先做"切片重写"——截取故事中最高压、最反常、最戏剧化的一个瞬间作为简介锚点。
4. 再用"三句法"检查前 3 句话：是否完成了"疑问 + 情绪 + 代入"三件事？如果前三句全是设定说明而非勾引读者，优先重写前三句。
5. 再写核心冲突与持续追读承诺。
6. **只对 `Agents.md` 中已注册的平台按平台长度收束语言、增强钩子与可传播句**；未注册的平台不生成适配版本。
7. 再按独立文件规则落盘并处理版本策略。
8. **最后执行"交易本质自检"**：如果读者在这里划走，ta 损失了什么？如果答案是"一段背景说明"或"设定名词"，回炉重写。

## 默认模型温度参考（新增）

创作简介需要适度创造性与语言变化，审计简介则需要稳定一致的判断力。

| 阶段 | 推荐温度 | 说明 |
|---|---|---|
| 撰写 / 重写简介 | 0.55 | 需要创造性但不宜跑偏 |
| 审计现有简介 | 0.3 | 低创造性，保持判断稳定 |

## 简介共性提醒（新增——吸收自知乎开篇精华）

- **交易本质**：写完简介后问自己——"如果读者在这里划走，ta 损失了什么？"如果答案是"一段背景说明"或"设定名词"，回炉。
- **信息差驱动**：简介不需要把故事讲明白，只需要让读者产生一个具体追问（"然后呢？""为什么？""谁干的？"）。这个追问就是点开的驱动力。
- **人际关系反常感**：简介中的人际关系反常（"和仇人相爱""妻子发现丈夫的秘密"）天然携带追问，比堆砌事件更有效。
- 简介默认优先交付情境与情绪共识，再补设定名词；若读者先看见一堆专有名词却没看见人物困境，视为失败信号。
- 主卖点最好压成“谁正在失去什么、必须做什么、为什么会越陷越深”这一条主钩，而不是平均陈列多个卖点。
- 若作品的持续吸引力建立在成长线、关系线或身份翻转上，简介里至少要让其中一条可被快速感知。
- 前 `1–2` 句默认还要承担 `30 秒归类` 任务：让编辑和读者能迅速判断这是什么书、主角正卡在哪个当下困局、继续看下去能得到什么。
- 若简介读完仍只能感知世界观名词，却感知不到人物处境、当前压力与持续承诺，默认按“设定说明化”处理并回炉。

## 默认输出口径

- 默认输出至少 1 个可直接使用的主版简介。
- 多平台场景下，默认补充长度差异或平台差异说明，但**只输出在 `Agents.md` 中已注册的平台对应的适配版本**，未注册的平台不输出。
- 若 `Agents.md` 不存在或未声明任何平台，只输出不区分平台的通用主版简介，跳过所有平台适配步骤。
- 若简介标题、正文说明、版本标识或落盘文件名需要出现作品名，统一使用本次交付对象对应的目标投放名。

## 落盘目录层级（强制）

- 本 Skill 的默认工作目录固定为 `小说简介/`。
- 系列全书简介、分部简介、分卷简介统一直接落在 `小说简介/` 根目录。
- 章节简介按小说结构分层：若作品有分部，统一落在 `小说简介/第X部/第Y卷/`；若作品无分部，统一落在 `小说简介/第X卷/`。
- 文件名继续服从日期与版本号规则，不得把章节简介散落到 `章节目录/简介/` 一类旁路目录。

## 最低交付

- 至少 1 个主版简介。
- 若涉及多平台，至少说明长版 / 中版 / 短版的适配差异，但**平台适配版本的数量受限于 `Agents.md` 中已注册的平台列表**，未注册的平台不交付。
- 前 1–2 句就能让编辑和读者快速感知主卖点，而不是读完整段还只看到设定名词。
- 必须让读者知道：谁、陷入什么局、为什么还会越陷越深。

## 硬规则

- 禁止只有世界观名词堆砌，没有情境与冲突。
- **禁止"大纲体"简介**：只堆砌设定要点和背景信息，却没有一个具体可感知的高压瞬间——这是简介最常见的败笔，和开头的"概括式叙述"是同一个病根。简介必须是"切片式"的。
- 禁止把全部反转提前剧透完。
- 禁止只说"命运齿轮开始转动"这类空口号。
- 禁止简介承诺一个正文里根本接不住的假卖点。
- **禁止前 3 句全是设定说明**：前 3 句必须承担"疑问 + 情绪 + 代入"三件事中的至少两件。如果前三句读者还不知道"该关心什么"，回炉。
- 不分部小说简介统一使用小说的目标投放名；分部小说简介统一使用对应部的目标投放名，不得继续沿用总书名顶替分部简介。
- **禁止为未注册平台输出简介版本**：任何未被 `Agents.md` 注册的平台，不得出现在平台适配简介的交付结果中。若 `Agents.md` 不存在或未声明任何平台，则只输出通用主版简介，跳过所有平台适配步骤。
- 除非用户明确要求只草拟，不得只在聊天里给简介而不落文件。

## 与其他 Skill / Prompt 的边界

- 本 Skill 负责简介文本本体。
- 不负责书名设计、书评撰写或投稿材料整体组包。
- **简介与开头的同构原则**：`通用-强化章节开头` 的"三句法""认知缺口""人际关系反常""切片 vs 大纲体""交易本质"等原则已被本 Skill 吸收为默认约束。若执行中遇到简介抓力不够但不知如何优化，可回读 `通用-强化章节开头` 的相关节获取更多灵感。
