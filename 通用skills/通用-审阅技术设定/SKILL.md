# 通用-审阅技术设定

审阅技术设定，重点不是“懂不懂技术”，而是“能不能进故事、能不能留下痕迹、会不会变万能”。

## 保真迁移要求（强制）

命中技术设定审阅任务时，除本文件外，**必须继续读取**：

- `references/技术设定审阅检查清单.md`
- `references/技术设定审阅报告增补.md`
- `references/审阅维度说明.md`
- `references/设定审阅报告模板.md`
- `references/腾讯专栏技术设定可证据化与边界风险增补.md`

## 风格/蓝本/写作研究模板自动发现规则

若当前服务的项目根目录存在 `Agents.md`，审阅技术设定前必须：

1. 读取项目根目录的 `Agents.md`；若其中声明了 `主输出平台`，检索三类模板时优先匹配"适用平台"与主输出平台一致的模板，无匹配时回退到"适用平台：默认"的同类模板
2. 若 `Agents.md` 中注册了"写作研究模板"——读取对应路径的模板文件，将其设定边界、解释比例、真实感和平台禁忌作为审阅基线
3. 若 `Agents.md` 中注册了"作者风格模板"——读取对应路径的模板文件，将其作为设定表达方式、叙事距离、句长段落和禁忌风险参照
4. 若 `Agents.md` 中注册了"作品蓝本模板"——读取对应路径的模板文件，将设定显影节奏、信息释放和阶段升级作为审阅参照
5. 本 Skill 只消费与技术设定审阅相关的字段；若模板字段与规则自洽、证据链或代价逻辑冲突，规则自洽和证据链优先
6. 若项目根目录不存在 `Agents.md`，或其中未注册对应模板——回退通用默认模式，不报错，不阻断

本 Skill 默认消费字段：

- 写作研究模板：设定解释比例、真实感要求、审核边界、代价机制、禁忌类约束
- 作者风格模板：叙事距离、句长基线、段落节奏、情绪表达方式、禁忌清单
- 作品蓝本模板：信息释放节拍、场景节奏分布、中段回报指纹、章首首秀方式

## 完整模板执行要求（强制）

- 产出设定审阅报告时，必须以 `references/设定审阅报告模板.md` 作为主骨架，不得退化成“几条规则点评 + 少量建议”的简版报告。
- 报告至少要完整覆盖：阅读链路确认、基础信息检查、写作落地卡片、设定用途一句话、首次出场与前三章验证、人物—情境—观点合拍度、规则条款清单、现实可行性与程序合理性检验、网文长线与规则演进复核、边界/代价/漏洞、可证据化映射、程序摩擦与现实阻力、误导与证伪窗口、现实痛点与情绪共鸣牵引、跨文档一致性总检、社会面/舆情面/合规预警、与人物/组织对齐、叙事落地建议、问题分级、评分、具体修改方案、冲击 9.2+ 综合评分的优化思路与总体结论。
- 对承担核心能力、主线程序链、关键证据载体或终局关门功能的设定，报告必须额外显式审：**一句话口径是否为动作→凭证→后果、触发条件 / 标准表现 / 失效规则是否完整、关键参数是否区分固定值与叙事弹性、最小调用流程卡是否成立、分级代价与程序痕迹是否可见、是否明确写出“不能直接解决的问题”、是否需要本轮修订 / 终局关门 / 残留余波块**。
- 若当前任务还加载了题材 Skill，则必须在通用骨架的占位章节中继续补写题材专项段、题材专项评分项与题材化结论重点。
- 报告中必须至少产出 `1–3` 张“写作落地卡片”，让作者能把规则直接拷回大纲、章节执行表或正文镜头。

## 网文长线与规则演进（强制）

- 审技术设定时，必须把它视为“能否撑住开篇抓力、中盘升级、终局回收”的长线引擎，而不是一次性炫技说明书。
- 必须显式判断：第一次出手怎么抓人、中盘如何升级、终局会产生什么更贵后果、代价是否能被正文真实感知、是否存在读者可讨论的误导点与证伪窗口。
- 若设定承担强能力或高概念机制，还必须显式判断：它的**最小可调用版本**是什么、第一次越界会留下什么程序痕迹、终局是否必须关门 / 降格 / 留余波。
- 若设定开篇就用尽最强功能、代价只存在文档里、或误导与证伪全靠作者解释，不得判为可用高分设定。

## planner / reviewer 镜像补强（新增）

- 审技术设定时，默认继续检查它是否具备 planner 风格的**规则分层与归档口径**：世界规则是否按地点 / 规则 / 势力 / 时间线 / 专项机制分层，是否只记录已确认事实，是否区分“作者知道的真相”与“角色知道的版本”。
- 若设定把未来计划写成既定事实，或把作者真相与角色口径混成一锅，默认判为规则层事故，而不是轻问题。
- 审阅报告里的问题默认标记来源层：`[规则条款层] / [载体证据层] / [阶段演进层]`。规则条款层看边界与代价，载体证据层看痕迹与取证，阶段演进层看首秀、中盘、终局与关门逻辑。
- 默认补一个 `Green / Yellow / Red` 入库判定：`Green`=规则、边界、痕迹、真相版本与阶段演进都清楚；`Yellow`=可用但仍缺证据载体、真相版本或终局关门块；`Red`=规则打架、万能化、无痕迹、真相版本混乱或首秀无法进正文。
- 审技术设定时还要复核写后更新条件：哪些变化该回写设定文档、哪些只是正文误写；否则审阅报告很容易只会挑错，不会告诉作者怎么维护规则体系。

## 网文首秀与读者供血（强制）

- 审技术设定时，必须判断它第一次出手是否能在前三章内咬到现实困局、留下可回指痕迹，并带来一次有效小回报、误判或代价。
- 必须显式判断：它是否绑定了最能凸显价值的代表性人物与熟悉日常情境；设定主要供血类型是什么（智性破局、恐惧打穿、制度反击、关系翻车、传播讨论、反差幽默）。
- 若设定首秀只能靠讲解、和人物 / 场景脱节，或没有可截图 / 可站队 / 可催更的钩子，不得判为网文高完成度设定。

## 起点爆款设定快筛与变现力评估（新增）

技术设定审阅时，默认还要判断：**这套设定是不是只“看起来很酷”，还是它真的具备起点爆款链路里的抓力、供血力与商业位支撑力。**

### 10 秒快筛（设定版）

把当前设定当作编辑快速理解项目卖点时会看到的机制核心，默认先做一次 `10` 秒快筛；命中以下 `3` 项及以上弱信号时，设定默认不得判高档：

1. **一句话机制口径是否成立**：是否能用一句“动作 → 凭证 → 后果”说清这套设定是什么、怎么起效、为什么危险。
2. **设定是否支持题材归类**：读者是否能迅速感知它属于悬疑机制、科幻机制、规则怪谈机制、都市异能机制中的哪一类，而不是“什么都沾一点”。
3. **首次出手是否有炸点**：它第一次登场是否天然带来异常、反差、规则错位、程序摩擦或现实后果，而不是只能靠讲解体现高级感。
4. **代价是否真实可见**：代价是否会在正文里留下痕迹、损耗、误判、暴露、反噬，而不是只写在设定文档里当安全阀。
5. **是否存在明确禁区**：是否写清“它不能直接解决什么问题”；若没有，默认按万能化高风险处理。

### 金手指 / 核心机制变现力复核

若设定承担主角核心能力、主线破局机制或题材最大新鲜点，默认必须补审以下三项：

1. **逻辑是否极简**：读者能否在开篇极短时间内理解“凭什么赢”；若需要先看三页说明书，判快审失败。
2. **变现力是否足够强**：它是否能让读者产生“如果我有这个能力/规则，我也想看它怎么改变命运”的代偿感；若只有概念新奇、没有使用快感，判供血不足。
3. **差异化是否成立**：它与同类竞品设定的本质差异是什么；若只是换皮面板、换皮外挂、换皮规则链，判为弱创新。

### 起点潜力分档（设定审阅辅助口径）

除 `Green / Yellow / Red` 入库判定外，按起点口径审技术设定时，默认允许再给一层“设定爆款助推档位”判断：

| 档位 | 判断标准 | 审阅含义 |
| --- | --- | --- |
| S | 机制口径清、首秀炸点强、代价可见、禁区明确、可持续升级且有讨论度 | 这套设定具备明显的抓人和供血能力 |
| A | 设定主干稳定，首秀与代价可用，存在局部边界或镜头化缺口但可快速修复 | 这套设定可作为长线引擎 |
| B | 规则基本成立，但首秀发虚、代价偏轻或差异化不足 | 这套设定能用，但还不够亮 |
| C | 万能化、讲义化、无痕迹、无禁区、无持续升级路径命中两项以上 | 这套设定会拖累题材说服力与追读 |

该分档只用于辅助判断“这套设定对整书爆款链路的贡献强度”，不得替代完整审阅结论与问题分级。

## IP 改编友好度 / 传播讨论点复核（新增）

技术设定若承担题材门面、主线抓手或世界观辨识度，审阅时默认还要判断它是否具备 **IP 改编友好度** 与 **传播讨论点**，因为这两项直接关系到作品的商业上限，而不只是正文可写性。

### IP 改编友好度复核

报告默认至少回答以下问题：

1. **可视化是否清晰**：这套设定能否被稳定转成镜头、音效、道具、UI、程序界面、异常现象，而不是只能靠解释理解。
2. **高光节点是否明确**：是否天然存在适合短剧 / 有声 / 动漫改编的高光出手、反转揭示、规则触发、证据翻面场面。
3. **调用成本是否适中**：设定是否过度依赖大段旁白、复杂参数、抽象概念，导致改编时必须先上课再看戏。
4. **衍生接口是否存在**：是否可以自然拆出配角线、旧案线、前史线、组织线，而不会一离开主线就失效。
5. **终局关门是否友好**：设定若必须在终局关门 / 降格 / 留余波，是否已经写清改编时的收束方式，而不是到结尾才临时收网。

若一套设定“正文里能写、改编里难演”，审阅报告应明确标成 **IP 友好度不足**，而不是只给“概念较复杂”的轻描淡写结论。

### 传播讨论点复核

起点爆款设定不仅要能用，还要能被读者讨论、截图、复述、站队。审阅时默认补查以下四类讨论点来源：

- **规则反常点**：一句话就能让人产生讨论欲的异常规则、悖论、失效条件。
- **现实刺点**：设定是否咬住现实焦虑、制度摩擦、身份风险、舆论压力、程序卡点等现实针脚。
- **立场分裂点**：同一设定下，不同角色是否会得出完全不同的选择，从而带来“你站谁”的讨论。
- **可截图物料点**：是否天然生成日志、回执、编号、术语、界面、警告语、录音转写、弹窗、制度条款等可传播载体。

若设定完整但没有任何一类稳定讨论点，默认判为“商业传播弱”；若四类里能稳定命中两类及以上，可在报告中标为传播潜力强设定。

### IP / 传播辅助分档

按起点口径审技术设定时，除前述设定潜力档外，默认还可补一条辅助判断：

| 档位 | 判断标准 | 含义 |
| --- | --- | --- |
| S | 可视化强、高光节点明确、讨论点密、可衍生接口自然 | 兼具正文抓力与改编传播价值 |
| A | 设定能演、能聊，存在个别抽象段但可镜头化修复 | 有明确商业放大空间 |
| B | 正文可用，但传播点弱、改编成本偏高 | 更适合文本内消费 |
| C | 讲义化严重、难演、难聊、缺传播载体 | 商业扩展性明显受限 |

该辅助分档主要回答“这套设定的商业放大量级”，不得替代规则自洽与正文可写性的基础审阅结论。

## 题材竞对分析接入要求（强制）

- 若当前任务服务某个题材，且该题材目录下的 `竞对分析/` 已存在与当前项目、当前平台或当前赛道相关的竞对分析报告，审阅前必须先读取并纳入对照。
- 若目标平台为起点中文网，或未注明平台但默认按起点口径处理，且当前题材目录下尚无可用竞对主报告，审阅前应优先调用 `通用-分析竞对作品`，至少补齐 **Top10 候选池、`3–5` 本主样本与四层深拆速览**；若任务限制导致本轮无法补齐，必须显眼记录盲区，并下调本轮审阅上限与置信度。
- 审阅报告不得只给内部自洽结论；必须显式判断当前设定相对竞对在哪些维度已领先、持平或落后，以及最先该补哪条超越路径。
- 若当前设定在竞对已验证的关键强点上明显更弱，必须直判为竞争风险；设定审阅默认按“严酷找差距”口径执行，不得为了安抚作者而把规则空转、代价失真或首秀发虚轻描淡写带过。
- 竞对维度在设定审阅综合评分中默认按 `25%` 计权；若未完成量化差距卡，或关键维度仍显著落后且没有 `72` 小时补丁，综合评分默认不得给高档。

## 起点化竞对吸收口径（新增）

当设定审阅服务起点中文网，或未标平台而默认按起点基线处理时，默认把竞对对照拆成以下四层，并翻译成审阅判断与补丁建议：

- **市场数据层**：用榜单位次、均订 / 首订 / 收订比代理信号、推荐资源位等，反推这套机制 / 手法是否真的支撑题材归类、持续付费价值与长线商业厚度，而不是只在作者视角里“设定很酷”。
- **内容创作层**：重点对照主样本在规则边界、失败条件、代价显影、证据链、误导与证伪、现实锚点、正文镜头包上的成熟度，把差距翻成规则级与镜头级补丁。
- **运营策略层**：重点对照主样本如何让机制持续供血、制造追读工程、讨论点、阶段升级感与推荐位适配，把差距翻成首秀、中盘、终局和关门逻辑的补丁。
- **受众反馈层**：重点对照本章说 / 书友圈 / 书评区里高频被夸的规则爽点、被骂的万能化病灶、老白读者对吃书 / 降智 / 失衡外挂的敏感点，把差距翻成避坑与加码建议。

起点语境下，默认尽量使用以下术语，而不是写成空泛的“设定竞争力不足”：`均订`、`高订`、`首订`、`追订`、`收订比`、`分类月票榜`、`畅销榜`、`新书榜`、`三江`、`本章说 / 段评`、`书友圈`、`老白读者`。拿不到精确值时必须写成代理信号，不得伪造具体数字。

## 常见触发词 / 用户说法速查

- 帮我审这份技术设定
- 看看这套规则是不是会万能
- 这份设定能不能进正文
- 证据化和程序摩擦够不够
- 给我设定审阅报告
- 这条规则边界是不是没写清

## 何时使用

- 审阅某个技术设定 / 手法 / 规则文档。
- 检查规则是否能拆条款、是否有边界、代价、漏洞与反制。
- 检查设定是否能落到日志 / 回执 / 编号 / 时间戳等载体。

## 报告落盘位置与命名规则（强制）

- 设定审阅报告必须落在项目根下的 `审阅意见/设定审阅报告/` 子目录中，不得散落在设定源文件目录或 `审阅意见/` 根目录。
- 设定审阅报告文件名必须带日期，日期格式固定为 `YYYY-MM-DD`。
- 推荐完整相对路径写法为 `审阅意见/设定审阅报告/设定审阅报告_[设定名]_2026-04-15.md`。
- 技术设定、手法、程序链、证据载体或规则文档本体默认不带日期；日期只用于对应审阅报告。

## 默认执行顺序

0. 若按起点口径执行且当前题材目录下缺少可用竞对主报告，先调用 `通用-分析竞对作品`，补齐 `Top10 候选池 → 3–5 本主样本 → 四层深拆` 的最小结论集。
1. 确认目标设定文件与关联剧情位置。
2. 若按起点口径执行，先吸收竞对主样本四层结论，并写清本轮审阅重点比对的关键项。
3. 先用检查清单做设定体检。
4. 再用审阅维度说明统一评分重心，并判断长线演进、误导—证伪与社会面后果。
5. 再按报告增补与报告模板输出可回写的审阅报告。

## 默认输出口径

- 默认输出一份带规则体检、风险分级与最小回写建议的设定审阅报告。
- 默认不直接改设定本体，除非用户明确要求边审边回写。
- 报告必须同时给出“作者向依据”和“正文镜头化改写抓手”，前者用于保证自洽，后者用于保证可写；不得只给说明书式建议。
- 报告必须同时回答“哪里失血”“最小怎么补”“补完后为何更抓人、更想追”，而不是只回答设定对不对。
- 默认同时输出：问题来源层、入库判定、最小规则级补丁、最小镜头级补丁与必要的回写触发条件。
- 若按起点口径执行，报告还必须显式覆盖：`Top10 候选池`、`3–5` 本主样本四层速览、竞对差距量化卡，以及当前设定最先该补的超越路径。

## 固定输出骨架（强制）

设定审阅报告默认按以下固定顺序输出，除非用户明确要求改版式，否则不得跳步或乱序：

1. **快筛结论**（10 秒）：先给机制是否可理解、可落地、可控风险的快速判断与阻断项。
2. **深评结论**（3 分钟）：再给规则边界、代价痕迹、证据链、镜头化、IP/传播友好度、竞对差距判断。
3. **分档结论**：给 `Green/Yellow/Red` + 起点口径潜力档（如 `S/A/B/C`）并写明依据。
4. **最小补丁链**：给“先改哪 `3` 条规则或镜头卡、每条改什么动作词”。
5. **72 小时动作**：给规则级回炉顺序、预计抬升项与复审触发条件。

若任务非起点口径，仍按同一骨架输出；其中竞对或平台字段可标注“本轮不适用”，但不得删掉骨架步骤。

## 最低交付

- 能指出规则条款、边界、代价、漏洞、反制与证据化问题。
- 能指出哪些问题会直接影响正文可写性。
- 能给出最小可回写补丁，而不是只说“设定还不够细”。
- 能产出至少 1 条可直接写回设定文档的规则级改写、至少 1 条可直接写进正文的镜头级改写，以及至少 1 条针对首秀 / 前三章回报的补丁。

## 复审独立性规则（强制）

- 每一轮设定审阅都必须把当前设定版本当作新的完整对象重新审查，不得仅因上一轮问题已修复，就把本轮判为高分或默认通过。
- 检查上一轮问题修复情况只是复审入口，不是复审主体；仍需独立重查规则条款、边界、代价、漏洞、反制、证据化、程序摩擦与镜头化落地。
- 若本轮发现新的万能化风险、新的规则冲突、新的证据链断裂或新的落地困难，必须如实记入本轮报告，不得因为“旧问题修好了”而跳过新问题。
- 本轮评分必须依据当前版本在本轮完整审阅下的实际质量给出，不得按修复率、修改投入或上一轮评分惯性顺延上调。

## 审阅重点

- 规则是否能拆条款
- 是否有边界、代价、漏洞、反制
- 是否能可证据化
- 是否具有程序摩擦和现实阻力
- 是否能写成镜头，而不是只能讲解
- 是否存在足够硬的现实痛点 / 情绪牵引 / 讨论度，而不只是“规则写得很全”
- 是否真的支持长线升级，而不是开篇一亮相就把底牌打完

## 硬规则

- 禁止只评价“设定是否酷 / 是否专业”。
- 若按起点口径执行，禁止跳过 `Top10 候选池 → 3–5 本主样本 → 四层对照` 就直接给高分或高档判断。
- 必须落到条款、边界、代价、证据化与回写动作。
- 必须说明设定第一次怎样进正文、最危险的万能点在哪里、最贵的后果会落到谁身上。
- 必须说明设定是否已经写清“不能直接解决的问题”、哪些参数绝不能漂、哪些红线一旦越过就该进入终局 / 关门逻辑。
- 必须说明设定前三章为什么值得读者继续跟，不能只给“后面会很厉害”的延期承诺。
- 禁止只给作者侧法条 / 资料依据，不给正文镜头、回执、对话或动作化落地方案。

## 与其他 Skill / Prompt 的边界

- 本 Skill 负责技术设定审阅与回写建议，不直接代替设定重写。
- 若用户要直接设计或补强技术设定，应优先使用 `通用-设计技术设定`。
