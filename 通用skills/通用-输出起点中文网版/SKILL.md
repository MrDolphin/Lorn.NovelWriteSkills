# 通用-输出起点中文网版

这是平台共性本体，负责承接"起点中文网版输出"的跨题材共性规则。

## 常见触发词 / 用户说法速查

- 输出起点版
- 改成起点能发的版本
- 做起点平台改写
- 帮我把这章改得更起点追读向一点

## 何时使用

- 把任意题材章节改写成更适合起点中文网平台读者的版本。
- 需要强化长线追读、章级回报工程、前 300/1000/3000 字分层抓力与类型辨识度。
- 需要为 `题材名-输出起点中文网版` 提供统一的平台骨架。

## 不适用情形

- 只做题材边界补充，不做平台输出本体。
- 只做多平台编排、落盘和终检，而不处理起点平台风格本身。

## 本层职责

- 维护起点中文网平台的跨题材共性规则。
- 统一承接起点版输出的结构约束、标题倾向、节奏压力与风格门禁。
- 为后续新增题材保留直接复用入口。

## 继续读取的 references

- `references/跨题材共性与迁移来源.md`
- `references/平台共性执行细则.md`
- `references/分节级补救映射与详细规则回填.md`

## 缓存优化说明

本 Skill 的结构遵循前缀缓存优化原则，调用时：

- **缓存层 1（永久不变）**：frontmatter + 本层职责 + 平台硬规则 + 禁行项 + POV 契约 → 每次调用完全相同，LLM API 的前缀缓存永久命中，按底价计费
- **缓存层 2（同平台内不变）**：平台模板自动发现规则 + references 清单 + 默认执行顺序 → 仅在切换平台或新增模板注册时变化
- **可变层（每次变化，不写入本文件）**：本次目标章节号、源稿路径、用户指定的特殊平台约束 → 由用户每次调用时指定，按正常输入价计费

人物传记、技术设定、写作研究模板等 references 通过 `## 继续读取的 references` 声明强制加载，其固定部分随本 Skill 一起进入缓存前缀。

## 平台模板自动发现规则

若当前服务的项目根目录存在 `Agents.md`，执行起点版输出前必须：

1. 读取项目根目录的 `Agents.md`
2. 若 `Agents.md` 中注册了三类模板，按以下优先级检索：
   - **优先**：模板注册时 "适用平台" 字段为 `起点` 的同类型模板
   - **回退**：模板注册时 "适用平台" 字段为 `默认` 的同类型模板
   - **忽略**：模板注册时 "适用平台" 指向其他平台的模板（如 `番茄`、`七猫`），本轮不加载
3. 若检索到匹配的三类模板——读取对应路径的模板文件：
   - 写作研究模板：作为起点平台的额外平台基线约束
   - 作者风格模板：作为起点版本保留底味和文风边界的参照
   - 作品蓝本模板：作为章首/回报/钩子结构保真的参照
4. 若项目根目录不存在 `Agents.md`，或其中未注册起点专属模板——回退通用默认模式，不影响正常输出
5. 本 Skill 的核心约束始终是：平台规则 > 安全合规 > 母稿事实 > 三模板约束。三模板是辅助，不改变平台输出规则

## 默认执行顺序

1. 先锁定源稿不可变层：事实、事件链、证据链、角色关系与因果顺序不得改坏。
2. 读取对应题材的 `题材名-输出起点中文网版` Skill，确认题材入口与路由关系。
3. 再读取本 Skill 的 `references/平台共性执行细则.md` 与 `references/分节级补救映射与详细规则回填.md`，执行起点平台的长线追读、章级回报与分层抓力强化。
4. 由题材包装层继续读取其题材 references，锁定题材边界、题材禁行项与题材专项补丁（作为兜底约束）。
5. 在"平台优先、题材兜底"前提下执行改写正文，确保平台化表达与源稿保真同时成立。
6. 最后才处理降相似度，不得为了降重破坏平台抓力。
7. 执行 POV 契约复核，确保与 `platformPovContract` 一致，不得出现未授权人称漂移。
8. 改写输出完成后，必须立即执行"输出后自检与修订"节的五项自检，不得跳过。
9. 若自检未通过，必须按结论回炉修订并复检，直至"自检通过/自检修订完成"后方可落盘。

## POV 契约与连续性（强制）

- 若本次由 `通用-多平台输出编排` 调度，必须继承该流程已锁定的 `platformPovContract`，不得在本 Skill 内重新决定人称。
- 若用户直接命中本 Skill，则必须在改写前先从源稿正文与当前平台已完成前序章节中推断并锁定 `platformPovContract`；默认优先级为：用户明确指定 > 当前平台已完成前序章节 > 源稿既有 POV 链路 > 本批次首个已通过章节。
- 未获批准不得把连续章节从第三人称静默改成第一人称，或反向漂移；若源章本来就是视角切换章 / 多视角连续章，只能按已登记 `switchPlan` 执行，不得临场换壳。
- 落盘前后都必须显式执行 POV 校验，并把结果写入日志或执行记录；中文平台默认使用 `scripts/pov_validate.py` 或 `scripts/run_pov_gate.ps1` 以 `lang=zh` 或 `auto` 复核正文区块，第三人称链路检查对话外第一 / 第二人称，第一人称链路检查对话外第一人称锚点。

## POV 选择指南（如无显式契约）

> **强制前置步骤**：必须首先读取工作区根目录 `Agents.md` 的 `## 平台POV基线表` 节，查找本平台的当前锁定人称。若基线表中无本平台条目，必须先在该表中创建条目并锁定人称（参考下方"适用场景分析"），再继续执行。
>
> **人称是全书级契约**：基线表锁定值即为本平台全书的唯一人称，不得逐章切换，不得章内混用（对话引用除外）。

若本次执行未获得上游明确的 `platformPovContract` 锁定，按以下指南为本平台适配稿确定人称（最终以 `Agents.md` 的 `## 平台POV基线表` 节锁定值为准）：

### 起点中文网版的人称适用场景（供创建/修订基线表条目时参考）

**平台底层逻辑**：起点中文网是男频付费阅读的标杆平台，读者付费意愿建立在"持续追读的欲望"上。起点读者耐心被大量内容充分训练，对开篇慢热、中段空转、章末无钩的容忍度极低。起点的人称选择核心是"信息控制"——读者应该知道多少、什么时候知道。

**为什么起点偏第三人称限知？**
- 起点主流题材（玄幻、仙侠、都市、悬疑）需要多角色承载与世界观铺展，第三人称限知视角天然适合"主角视角跟随 + 必要时的视角切换"。
- 第三人称限知允许作者在保持主角代入感的同时，通过限制性描写制造信息差——读者和主角一起发现、一起误判、一起翻盘。
- 起点读者习惯了"他/她"叙事，第三人称是默认舒适区。用第一人称开篇会增加读者摩擦成本，除非题材本身就是推理/亲历型。

**什么时候起点应该用第一人称？**
- 题材本身是强亲历型——都市悬疑（第一人称推理专用）、灵异志怪（"我"经历的诡异事件）。
- 故事核心魅力在于主角的内心声音与独特视角，第一人称能形成强烈的"贴脸感"与观点压强。
- **警告**：起点第一人称必须做到"限知第一人称"——只写"我"看到的、听到的、感受到的。不能写出"后来我才知道"的预叙腔，也不能在对话外替其他角色宣布内心活动。

## 默认输出口径

- 默认输出一版可直接继续落盘或进入平台终检的起点派生正文。
- 默认保留原章核心事件链、抓点节拍与章末驱动，不新增关键事实。

## 最低交付

- 有明确的起点平台长线追读感、章级回报与章末强驱动。
- 保住原章核心事件链、读屏顺滑度与追读驱动。
- 读起来不像泛网文稿，也不像硬压缩摘要稿。

## 输出后自检与修订（必做，不得跳过）

改写输出完成后，必须立即执行本节自检；根据发现的问题就地修订，确认通过后方可落盘。**不得以任何理由跳过本步骤。**

**五项自检：**

0. **字数达标**：正文和 `## 作者有话说` 必须先满足本 Skill 的字数门禁；正文未达硬下限前，不得进入后续自检，必须先回炉补足字数。**严格禁止为凑字数进行模板化补字或机械扩写**；若检测到模板句污染、解释腔堆砌或无意义重复，则判定字数虽足但自检失败，必须重写。
1. **零新增事实**：改写版未引入源稿中不存在的关键事实、人物或设定；引入则删除/还原。
2. **核心事件链完整**：起因→推进→高潮→章末钩子方向均在改写版中体现；断裂则补回。
3. **平台风格达标**：改写版满足本 Skill"最低交付"所列各项；不足则就地修订。
4. **无模板句污染**：未出现连续 2 句及以上解释腔/模板腔/口径名词句群；命中则整段回炉。
5. **POV 一致**：改写版 POV 与已锁定的 `platformPovContract` 一致；漂移则回炉修正。

**结论格式（必须输出）：**

- 全部达标：`[自检通过] 五项均达标，可落盘。`
- 已修订达标：`[自检修订完成] 已修订：<问题描述>，现五项均达标，可落盘。`
- 未通过（不得落盘）：`[自检未通过] 命中：<问题描述>，需继续处理。`

命中"未通过"后必须修订并重新输出自检结论，循环直至输出"通过"或"修订完成"方可落盘。

## 硬规则

- 绝对禁止输出"抽象自述 + 动词模板 + 口径名词"的垃圾句群；凡出现类似"对照项落在… / 先把同一句话拆碎 / 先把顺滑的解释拆开 / 只求能追溯（复核、对得上）"等模板化短语，必须判定为污染并整稿回炉。
- 严禁使用或间接调用以下脚本对正文做生成、扩写、拼接或降重：`scripts/append_cn_unique_monologue.ps1`、`scripts/append_cn_unique_narration.ps1`、`scripts/append_cn_unique_thirdperson.ps1`、`scripts/rephrase_cn_body.ps1`、`scripts/rephrase_en_body.ps1`、`scripts/cn_lexicon_profile_transform.ps1`。这些工具不得进入平台正文生产链路。
