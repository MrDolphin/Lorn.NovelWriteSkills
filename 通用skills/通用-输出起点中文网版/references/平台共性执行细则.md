# 通用-输出起点中文网版｜平台共性执行细则

## 适用目标

将章节改写成更适合起点中文网平台的版本，同时保持：主要信息不丢失、长线追读节奏更强、输出仍为纯小说正文。

## 平台共性任务定义

- 强调长线追读、章级回报工程、类型辨识度与章末强驱动。
- 保留关键事件链、关系变化、风险升级与章末钩子。
- 不允许新增事件、证据、人物、地点、时间点或因果。
- 平台核心指标为"追读率、收藏/追订转化、本章说活跃度、推荐票/月票反馈"，不接受开头慢、中段空转、章末无钩的文本。

## 共同硬约束

- 正文必须是小说，不得写成清单、总结、教程或讲解稿。
- 输出文件只允许：章标题、正文、`## 作者有话说`。
- 正文字数以 CJK 计，推荐在 2500–4500 之间（以本 Skill 的"平台默认字数范围"或项目 `Agents.md` 覆盖值为准）。
- 作者有话说以 CJK 计，推荐在 200–300 之间（以本 Skill 的"平台默认字数范围"或项目 `Agents.md` 覆盖值为准）。

## 起点平台节奏共性

- 起点属于付费阅读 + 追读驱动平台，核心是"读者愿意为下一章付费"的持续动力。
- 核心用户以 18–35 岁男性为主，阅读量大、耐心有限、类型辨识度高。
- 开头必须快速进入冲突或异常——前 300 字无冲突则读者流失。
- 前 1000 字必须亮出金手指或明确回报预期——读者需要知道"主角凭什么能赢"。
- 章内必须有阶段回报，不能通章只铺不收。
- 章末必须给出清晰的下一章阅读动机——新缺口、新代价、未完成动作或更危险的新解释。
- 3–5 章应有小回报（阶段兑现），10–15 章应有大回报（卷级兑现）。
- 点击→阅读转化率若低于 40%，必须优化开篇抓力。

## 起点的表达原则

- 段落适中，单段 2–5 句构成一个阅读单元；过短则信息密度不够，过长则移动端阅读疲劳。
- 动作推进与人物选择优先于环境描写和内心独白。
- 场景描写必须同时承担至少一种功能：推进剧情、埋伏线索、加重风险、强化情绪。
- 对话应有立场碰撞或信息释放，避免纯寒暄。
- 信息释放遵循"先炸再解释"——先让异常发生，再通过人物反应和碎片信息逐步展开。
- 禁止上帝视角：不写别人内心活动、不替角色宣布情绪、不预叙未来。

## 起点的回报与钩子密度

- 每章至少保证一次清晰阶段回报，不能通章只铺不收。
- 章内节奏：前 300 字入冲突 → 前 1000 字亮金手指/回报预期 → 中段至少一次回报 → 章末强钩子。
- 章末钩子优先落在：新缺口、新代价、未完成动作、更危险的新解释、关系翻面、新线索落针。
- 钩子类型应按"终止→悬停→揭示→转折→危机→执行"做章间轮换，避免连续多章同类型钩子。
- 回报最好是"读者看懂了什么"或"主角赢得了什么"，而不只是"发生了什么"。

## 起点平台的开篇量化标准

起点读者的耐心已被大量内容充分训练，以下数字不是建议而是生存线：

### 前 300 / 1000 / 3000 字的硬性密度要求

- **前 200 字**：必须有强钩子。若前 200 字无冲突、无异常、无压力信号，80% 用户会直接划走。不要写景、不要介绍世界观、不要交代人物背景——直接让异常或冲突发生。
- **前 300 字**：必须"扔炸弹"——突发意外、强烈反差、或一个让读者立刻感知危险的信号。此时读者应该已经有了一个具体的问题在心里（"他怎么办？""这是什么？""谁在搞鬼？"）。
- **前 1000 字**：必须"亮金手指"或至少给出明确的回报预期。读者需要知道"主角凭什么能赢"或"这个故事会往哪个方向走"。禁止到 1000 字还在铺垫氛围。
- **点击→阅读转化率**：若实际发布后该数据低于 40%，必须立即优化开篇——说明首屏没有形成足够的抓力。

### 开篇四大毒点（逐项自检）

以下四种开篇方式已被大量失败案例验证会直接劝退起点读者：

1. **慢热铺垫型**：开头大量描写环境、介绍世界观、交代人物背景，而不是直接进入冲突。修正：把最炸裂的矛盾直接切到第一句。
2. **信息过载型**：短时间内冒出太多配角名字、专有名词、设定术语，读者记不住也懒得记。修正：第一章出现的需要读者记住的名字控制在 3 个以内，其余用"那个穿灰夹克的男人"等感官特征替代。
3. **主角受气型**：开篇让主角一味受欺负、被误解、被碾压，却没有给反抗或逆袭的明确苗头。修正：即使主角眼下处于劣势，也必须在前 1000 字内让读者看到"他会反击"的信号——一个眼神、一个念头、一个被藏起来的动作。
4. **长篇回忆型**：穿越/重生后用大量篇幅写前世回忆或原身记忆，而不是让主角立刻面对眼前的麻烦。修正：回忆信息用碎片化方式在行动间隙插入，每次不超过两句话，不得超过三次。

## 起点平台的黄金三章规则

- **第一章**：抛出核心冲突。直接把主角扔进麻烦里，让读者跟着紧张。
- **第二章**：强化主角困境。形势更危急，压力更大。
- **第三章**：埋下核心悬念。一个足以牵扯出整个故事的秘密。

**千万不要铺垫** —— 直接把主角扔进冲突里。

## 起点平台的竞对吸收口径

当控制卡/章末/章首等服务起点中文网时，默认把竞对吸收拆成以下四层，并翻译成写前施工约束：

- **市场数据层**：用榜单位次、均订 / 首订 / 收订比代理信号、推荐资源位等，反推本章在抓力、回报、续读驱动与题材归类效率上至少该达到什么强度。
- **内容创作层**：重点吸收主样本在章首切入、动作链、信息差、人物抓手、规则边界、回报位与钩子位上的做法。
- **运营策略层**：重点吸收主样本的追读工程、本章说讨论点、更新节奏匹配、卷首/卷尾功能位与评论触发设计。
- **受众反馈层**：重点吸收本章说/书友圈/书评区里高频被夸的值点、被骂的拖点、老白读者不耐烦的病灶。

起点语境下默认尽量使用以下术语：`均订`、`高订`、`首订`、`追订`、`收订比`、`分类月票榜`、`畅销榜`、`新书榜`、`三江`、`本章说 / 段评`、`书友圈`、`老白读者`。拿不到精确值时必须写成代理信号，不得伪造具体数字。

## 起点平台的核心驱动力设定

写正文前必须先回答：**读者为什么要跟着这个人物走？他们在等什么？在担心什么？**

故事框架：**某人 → 渴望 → 遇阻 → 改变**

- 某人：一个具体的角色
- 渴望：他想要什么（要具体）
- 遇阻：什么力量阻止他（要有真实代价）
- 改变：他最终怎样改变（要不可逆）

## 起点平台的创作视角铁律

- 写正文前先确定：摄像头架在谁的肩上？这一章读者透过谁的感官在看世界？
- **摄像头视角**：只写主角看到的、听到的、闻到的、身体感受到的。主角不知道的事，读者就不能提前知道。
- **禁止上帝视角偷跑**：不写别人的内心活动、不写远处发生的事、不替角色宣布"他很害怕"——让角色自己的身体反应出来。
- 前 300 字内必须建立视角归属；若读者读了三段还不知道"跟着谁"，就是视角塌了。

## 起点平台的读者向作者有话说

- 默认按读者向小剧场处理：一丢丢创作花絮 + 一点贴着本章余波的情绪共鸣 + 一个开放式轻追问。
- 不写成章节点评、创作总结或设定讲义。
- 不得在作者有话说中直接预告下一章内容。

## 统一9步编排母模板（平台优先，题材兜底）

1. 先锁定源稿不可变层：事实、事件链、证据链、角色关系与因果顺序不得改坏。
2. 读取对应题材的 `题材名-输出起点中文网版` Skill，确认题材入口与路由关系。
3. 再读取本 Skill 的 `references/平台共性执行细则.md`，执行起点平台特异强化。
4. 由题材包装层继续读取其题材 references，锁定题材边界、题材禁行项与题材专项补丁（作为兜底约束）。
5. 在"平台优先、题材兜底"前提下执行改写正文，确保平台化表达与源稿保真同时成立。
6. 最后才处理降相似度，不得为了降重牺牲平台读感与题材关键抓手。
7. 执行 POV 契约复核，确保与 `platformPovContract` 一致，不得出现未授权人称漂移。
8. 改写输出完成后，必须立即执行"输出后自检与修订"节的五项自检，不得跳过。
9. 若自检未通过，必须按结论回炉修订并复检，直至"自检通过/自检修订完成"后方可落盘。
