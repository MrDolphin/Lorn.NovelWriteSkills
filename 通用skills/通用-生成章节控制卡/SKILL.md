# 通用-生成章节控制卡

控制卡不是摘要，而是施工命令。它要回答“这一章怎么写”，而不是“这一章大概写什么”。

## 保真迁移要求（强制）

命中写前控制任务时，除本文件外，**必须继续读取**：

- `references/章节标准模板与钩子轮换施工卡.md`（**必读** — 写前节拍模板与钩子轮换）
- `references/章节控制卡保真规则.md`
- `references/章节控制卡模板.md`
- `references/场景单元拆分法.md`
- `references/中段回报与章末钩子检查表.md`
- `references/爽点递进与300_1000_3000节奏锚点.md`
- `references/九部件预埋与进度节奏微表.md`
- `references/上游供血对齐与回填接口表.md`
 - `references/腾讯专栏动作反应施工增补.md`
 - `references/腾讯专栏情节细节坐标轴与新人禁忌增补.md`
 - `references/腾讯专栏动作反应两对完整结构增补.md`
 - `references/腾讯专栏情节细节坐标轴与新人九项禁区增补.md`
- `references/唯一职责_beat_情感弧_钩子链_就绪判定补编.md`

## 缓存优化说明

本 Skill 的结构遵循前缀缓存优化原则。控制卡是写前施工的高频调用任务（每章一次），调用时：

- **缓存层（永久不变）**：frontmatter + 核心任务清单 + 中段回报/章末钩子的判定标准 + 就绪判定规则 → 每次调用完全相同，按底价计费
- **项目层（同项目内不变）**：references 清单 + 题材竞对分析接入要求 + 风格/蓝本模板自动发现规则 → 仅在切换项目或新增模板注册时变化
- **可变层（每次变化，不写入本文件）**：本次目标章号、上游卷纲/章纲内容、本章特殊约束 → 由用户每次调用时指定
- 人物传记、技术设定、卷纲等上游文件通过 references 声明强制加载，其固定部分随本 Skill 一起进入缓存前缀

## 卖点保真要求（强制）

- 每张控制卡都必须说明：本章对主卖点的关系是强化、兑现、转化、保温还是暂时铺垫。
- 若本章不是卖点显性回报章，也必须写清它怎样避免卖点断供，以及下一次卖点回报将在何处接棒。
- 若控制卡无法说明“这一章读者为什么还会继续记得本书卖点”，说明本章准备仍不合格。
### 仿写场景下的引擎保真施工（新增 — 当存在作品蓝本模板时强制）

当 `Agents.md` 中注册了"作品蓝本模板"且当前项目为仿写场景时，生成控制卡前必须：

1. 读取蓝本模板的 **§十七 仿写内核卡** 中的"核心爽感引擎"和"金手指-主线绑定模式"
2. 确认本章对核心爽感引擎的关系——是以下哪一类：
   - **显性兑现**：本章让读者直接感受到引擎的快感（如爽文的反击/打脸章、悬疑的线索揭示章）
   - **隐性蓄力**：本章为下一次显性兑现做准备（如信息收集、资源积累、关系铺垫）
   - **引擎升级**：本章扩展了引擎的能力边界（如金手指升级、规则边界突破）
   - **引擎转向**：本章把引擎引向新的问题链方向（如问题漂移的转折点）
3. 若连续 3 章没有显性兑现核心爽感引擎，视为**引擎失温**——即使结构上没犯错，读者也会开始感觉"这本好像没有当初看蓝本时那种感觉了"
4. 在控制卡中显式写出：**本章对核心爽感引擎的贡献类型**
5. 同时检查**本章的情节密度是否匹配蓝本的同位置预期**：
   - 若蓝本在第 10 章左右的节奏特征是"事件密集、快速推进"，本章的控制卡不能安排成"缓慢过渡、氛围为主"
   - 若需要放慢节奏（如核心角色死亡后的哀悼章），应在控制卡中**显式标注放慢的理由**，否则按节奏失配处理
6. **因果倒置与结构重组选项（读取蓝本§十七 仿写内核卡后判断）**：
   - 若蓝本内核卡标注了"因果倒置适用方向"，则判断本章是否适合使用因果倒置——即把蓝本同位置章节中"因为 A 所以 B"的逻辑翻转为"因为 B 所以 A"
   - 若使用因果倒置，控制卡必须写清：原因果链是什么、倒置新逻辑是什么、引擎是否仍能运转
   - 若蓝本内核卡标注了"适用结构重组技法"，则判断本章是否对应某个技法（如"线索合并""模块化设计"等），若适用则写进控制卡施工要求

### 控制卡密度门槛（新增）

控制卡要足够"密"——下游写手拿到后能直接开工，不需要自己补剧情或推断"这一章到底要发生什么"。密度门禁标准：

1. 每个场景单元必须有明确的入场状态、冲突对象、目标与退场状态
2. 中段回报与章末钩子必须写明具体类型与触发条件，而非泛写"有回报"
3. 若控制卡读完仍需要写手自行补充中间过程，判定为密度不足
4. **情节密度三档标注（仿写场景强制）**：当本章参照蓝本的同位置章节时，在控制卡顶部标注本章的情节密度档位：
   - **高密度（事件压缩）**：本章要把蓝本中 X 章的内容压进 1 章——控制卡必须写清哪些事件被合并、如何合并
   - **中密度（节奏对齐）**：本章的节奏密度与蓝本基本一致
   - **低密度（细节扩展）**：本章把蓝本中的某个关键瞬间扩展为独立章——控制卡必须写清扩展的内容是什么、为什么值得扩展
## 题材竞对分析接入要求（强制）

- 若当前任务服务某个题材，且该题材目录下的 `竞对分析/` 已存在与当前项目、当前平台或当前赛道相关的竞对分析报告，生成控制卡前必须先读取并纳入本章施工判断。
- 若已配置主输出平台，且当前题材目录下尚无可用竞对主报告，生成控制卡前应优先调用 `通用-分析竞对作品` 补齐最小结论集；若任务限制导致本轮无法补齐，必须显眼记录盲区，并降低本章开写就绪判定。竞对分析的目标平台由主输出平台配置决定。
- 不得把这些报告只当成背景资料；控制卡必须显式说明本章准备在哪些维度追平、反超竞对，以及哪些旧坑必须避开。
- 控制卡的默认目标不是“能开写就行”，而是让当前作品在关键维度上**全方位超越竞争对手**；若看不出明确超越路径，应继续补施工而不是草率开写。
## 风格/蓝本模板自动发现规则

若当前服务的项目根目录存在 `Agents.md`，生成控制卡前必须：

1. 读取项目根目录的 `Agents.md`；若其中声明了 `主输出平台`，检索三类模板时优先匹配"适用平台"与主输出平台一致的模板，无匹配时回退到"适用平台：默认"的同类模板
2. 若 `Agents.md` 中注册了"写作研究模板"——读取对应路径的模板文件，将其结构类约束（节奏间隔、回报间隔、钩子强度分级、章首约束）和禁忌类约束作为本章控制卡的默认约束基线
3. 若 `Agents.md` 中注册了"作品蓝本模板"——读取对应路径的模板文件，将章首模式指纹、钩子轮换规律、中段回报间隔作为本章控制卡的参照约束（如选择章首切入方式和钩子类型时参照蓝本指纹）
4. 若 `Agents.md` 中注册了"作者风格模板"——读取对应路径的模板文件，将其文笔约束传递给下游的正文创作和场景施工环节
5. 若项目根目录不存在 `Agents.md`，或其中未注册对应模板——回退通用默认模式，不报错，不阻断

## 主输出平台自动发现规则

若当前服务的项目根目录存在 `Agents.md` 且其中声明了 `主输出平台`，生成控制卡前必须按命名约定加载对应的 `通用-输出{平台名}版` Skill，将其开篇量化标准、回报与钩子密度、章节节奏节拍与平台门禁作为本章控制卡的默认约束基线。若未配置主平台或配置缺失，回退通用默认模式，不阻断。

## 平台竞对吸收口径

当已配置主输出平台时，默认把竞对吸收拆成以下四层，并翻译成写前施工约束。具体平台术语与指标由主输出平台对应的 `通用-输出*版` Skill 提供：

- **市场数据层**：用平台关键指标代理信号反推本章在抓力、回报、续读驱动与题材归类效率上至少该达到什么强度。
- **内容创作层**：重点吸收主样本在章首切入、动作链、信息差、人物抓手、规则边界、回报位与钩子位上的做法，把它翻成控制卡里的唯一职责、四拍分配、场景职责与风险提示。
- **运营策略层**：重点吸收主样本的追读工程、讨论点设计、更新节奏匹配、关键章功能位与评论触发设计，把它翻成中段回报与章末留钩施工要求。
- **受众反馈层**：重点吸收平台读者高频被夸的值点、被骂的拖点、读者不耐烦的病灶，提前写进本章控制卡的避坑和加码清单。

## 常见触发词 / 用户说法速查

- 这一章到底要推进什么
- 帮我拆成几个场景单元
- 这章的中段回报是什么
- 写前作战卡 / 施工卡
- 哪些冷线该在这章回来了

## 何时使用

- 在正式写章节前，需要把卷纲 / 章纲压缩成可执行的本章控制卡。
- 中段容易塌，需要先明确本章任务、回报、冷线回归和钩子。
- 用户希望先看章名候选、POV、节奏档位、场景单元，再决定是否动笔。

## 本 Skill 的核心任务

每张控制卡至少要写清：

1. 本章**必须改变什么**。
2. 哪条线要推进，哪条线要回归。
3. 本章中段的**明确回报**是什么。
4. 本章的主要场景单元和压力变化。
5. 本章风险：最容易写崩的点是什么。
6. 章末留给下一章的钩子类型与对象。
7. 本章怎样让主卖点继续被看见或被记住。

## 最小核心与问题引擎校验（新增——吸收自知乎精华）

- 开卡前必须先写一句"最小核心"：`谁在什么处境下，为了什么目标，正被什么阻力压迫`。
- 若该章属于第一章或卷首章，控制卡必须显式写出"问题引擎"：读者看完本章后心里要留下的具体追问是什么。
- **问题引擎的优先类型——人际关系反常**（来自陈野亮理论）：最有效的问题引擎不是"这件事的结果是什么"，而是"这两个人之间到底是什么关系？为什么他们会这样？"——让读者对人际关系的真相产生追问，比让读者对事件结果产生追问更具黏性。
- 若控制卡只有信息点、设定点、背景点，没有可被读者追问的问题，视为未达开写条件。
- “问题引擎”必须与本章动作链绑定，不能只写抽象悬念词（如“真相如何”）而没有现场触发物。

## 章节四拍与首屏控制（新增——吸收自知乎精华）

- 控制卡默认要写清本章的四拍分配：**钩子、蓄力、爆发 / 回报、留钩**，至少说明哪一拍最重、哪一拍绝不能缺位。
- 若本章承担卷首、卷中转折或关键续读职责，控制卡里必须显式写出前 `300` 字准备让读者看到什么人物抓手、眼前麻烦或反常信号。
- **首屏抓力优先使用"人际关系反常"**（陈野亮式）：让读者第一眼看到的不只是"有事发生"，而是一段反常的人际关系正在展开。宁可让读者先看到"妻子的手机上出现了一条不该出现的消息"，也不要先写"她今天工作很忙"。
- **"交易本质"自检**：控制卡写完首屏部分后，问——"读者读完前 300 字如果关掉，ta 得到了什么？"如果答案是"背景交代"或"气氛铺垫"，说明首屏没有完成交易。- **"切片开头"指令（新增——包罗万象式）**：控制卡中首屏部分不得写成"大纲式概括"（如"主角被公司开除，心情低落"），必须写成"切片式瞬间"——指定一个最高压、最反常、最戏剧化的具体画面作为开篇锚点。若控制卡的首屏描述是概括性的而非场景性的，视为未达开写条件。
- **"三句法"写前检查（新增——包罗万象式）**：控制卡写完首屏指令后，检查：开篇三句话是否各自承担了"疑问/情绪/代入"中的至少一项？如果有任何一句只是"信息说明"而非"勾引读者"，标记为这条控制卡的风险点，在写正文前须先解决。- 中段回报不能只写“推进了主线”；必须写成读者可感知的具体收益：关系推进、误判修正、局面反击、信息开口、身份抬升或代价落地。
- 若本章主要是保温章，也必须写明如何维持卖点可见度，避免连续多章只有流程推进没有值回票价的变化。

## 人物执行要求（新增——强制）

> 核心问题：控制卡规划了本章"发生什么"，但如果没有同步规划"人物怎样被看见"，正文写出来就容易变成情节流水账、人物面目模糊。

生成控制卡时，必须从出场人物的传记中提取"正文可调用素材清单"（见 `通用-设计人物传记/references/正文可调用素材清单.md`），并写入控制卡的场景单元中。每一章至少完成以下三项中的两项：

### 人物执行三必查

1. **每个人物在本章至少要有一个"只有他会这样做"的瞬间**
   - 来源：传记中的决策启发式、压力反应微镜头
   - 落位：控制卡场景单元的 beat 描述中必须显式标注"人物动作来自 XX 心智模型/启发式"
   - 反例：人物在本章只是"出现、说话、推动信息"，但没有做出任何体现其独特认知规则的选择

2. **每段高冲突对话必须至少有一个人物展现了声口特征**
   - 来源：传记中的声口即时贴、表达DNA
   - 落位：控制卡的场景单元"对话链"中必须标注"人物 X 的声口特征：短句/断言/不问只判"
   - 反例：遮住名字后，对话双方说的话可以互换——这说明声口未分化

3. **若本章场景与某个人物的诚实边界/误判预设场景匹配，必须触发至少一次**
   - 来源：传记中的诚实边界、误判预设场景
   - 落位：控制卡的"中段回报"或"章末钩子"中标注"本章触发了人物 X 的 XX 盲区/误判"
   - 反例：人物传记写了"他看不懂纯情感驱动的行为"，但本章他面对朋友哭诉时应对自如

### 人物执行要求的记录格式

控制卡中每个场景单元的人物参与字段，默认按以下格式补齐：

```markdown
### 场景单元 N：人物执行要求

**出场人物与本章行为锚点**：
- [人物A]：本章要体现的心智模型 → [具体哪个模型]；来自传记压力反应微镜头 → [哪个微镜头]；本章标志性动作/判断 → [一句话]
- [人物B]：本章要体现的决策启发式 → [具体哪条]；来自传记声口即时贴 → [哪句/哪种情境]；本章标志性台词 → [一句话]
```

### 传记素材缺失时的降级处理

- 若出场人物传记缺少正文可调用素材清单，控制卡必须标注"人物 XX：传记缺正文可调用素材，本章人物执行靠写手即兴发挥"
- 若核心人物连续 3 章控制卡都出现此标注，必须在控制卡风险提示中记录"人物空心化风险：传记未提供可执行素材，人物可能逐渐失去辨识度"
- 此标注同时作为信号，提示应回补传记的正文可调用素材清单

## 唯一职责、beat、情感弧与就绪判定补强（新增）

- 每张控制卡都必须单列“**本章唯一职责**”与“**不应包含**”：唯一职责需要能用一句话说清本章让读者完成什么认知 / 情绪 / 追问；不应包含则负责声明哪些线、不该在哪些位置抢跑的解释与结论不在本章处理。
- 每个场景默认补齐：`POV`、场景目标、情感转变、参与角色、情感基调、冲突 / 张力来源、信息流、与下一场景的关系、过渡方式、建议字数。
- 每个场景默认拆 `1–4` 个 beat，并标 `承重 / 灵活`；承重 beat 负责本章叙事承重，默认不得删除或无故换序，灵活 beat 可合并、弱化或换实现方式。
- 情感弧必须写清读者情感入口、读者情感出口与弧线模式；若入口出口几乎无变化，本章大概率会读感发平。
- 控制卡尾部默认补一张“钩子链验证”：上章出口钩、本章入口响应、本章出口钩、下章预期响应；上章钩子断裂且无解释，默认降级处理。
- 就绪判定默认分 `Green / Yellow / Red`：`Green`=职责、beat、情感弧、钩子链、节奏权重、字数分配都齐；`Yellow`=缺 `1–2` 个非核心项但 writer 可谨慎推进；`Red`=唯一职责说不清、承重 beat 漏失、钩子链断裂、连续重章无调整方案等，需先回炉。

## 执行顺序

0. 若按起点口径执行且当前题材目录下缺少可用竞对主报告，先调用 `通用-分析竞对作品`，补齐 `Top10 候选池 → 3–5 本主样本 → 四层深拆` 的最小结论集。
1. 读取上游卷纲 / 章纲 / 单元案 / 相关台账。
1.5. **读取本章出场人物的人物传记**，重点提取"正文可调用素材清单"（压力反应微镜头、声口即时贴、误判预设场景、关系拉扯动作库）；若传记缺少此清单，在控制卡中标注降级。
2. 若按起点口径执行，先吸收竞对主样本四层结论，并写清本章要追平 / 反超的关键项。
3. 先做冷线与债务扫描，再决定本章要承接谁。
4. 先钉死六件事：核心改变、主推进线、回归压力、中段回报、主要风险、章末钩子。
5. 先用“上游供血对齐与回填接口表”钉死本章承接哪个故事面、位于本卷哪一段、属于显性回报章还是保温章。
6. 若本章结构位置发虚，先用“九部件预埋与进度节奏微表”确认本章所在段落与 3–5 个节拍。
7. 按模板输出控制卡：身份、任务、回报、场景、风险、标题候选、钩子。
8. 若控制卡无法说清中段回报，说明本章仍未准备好。
9. 若本章需要拆成 3–5 个较清晰的动作单元，继续按场景单元拆分法展开。
10. 输出结果优先服务正文创作，而不是取代正文创作本身。

## 默认输出口径

- 默认输出一张可直接服务正文创作的控制卡。
- 默认同时检查卷纲、冷线、回报、章末钩子与章名候选。
- 默认同时输出“唯一职责 / 不应包含 / 情感弧 / beat / 钩子链验证 / 就绪判定 / writer 注意事项”。
- 若用户只要极简控制卡，也至少不能删掉“中段回报”和“章末钩子类型”。
- 若任务是长篇连载，默认同时检查前 300 / 1000 / 3000 字的节奏锚点与爽点递进。

## 最低交付

- 能解释这章为什么非写不可。
- 能一句话说清本章唯一职责，并写清本章不该提前处理什么。
- 能指出本章主推进线。
- 能指出本章中段回报。
- 能指出本章与主卖点的关系。
- 能拆出 3–5 个带压力变化的场景单元。
- 能说清本章风险与钩子类型。

## 本章在全篇节拍地图中的定位（新增）

生成控制卡时，必须先判断本章位于全篇节拍地图的哪个区间，再据此校准本章的节奏权重与爆点强度：

| 章节区间 | 本章所处区间的核心任务 | 对控制卡的约束 |
| --- | --- | --- |
| 1–10 章 | 建立世界观、核心冲突、主角目标 | 每 2–3 章必须有一个小钩子；若本章处于钩子位，章末钩子强度不得低于"新危机"或"新代价"级 |
| 11–30 章 | 第一个大副本，展示成长体系 | 每 5 章必须有一个中等爆点；若本章处于爆点位，中段回报必须是读者可感知的具体收益 |
| 31–50 章 | 关系深化，铺垫中期危机 | 埋伏笔为主，但每章仍需至少一处关系位移或信息推进 |
| 51–70 章 | 中期高潮，世界观第一次扩展 | 每 3 章一个爆点；控制卡必须显式写清本章如何为下一个爆点蓄力 |
| 71–100 章 | 终极冲突铺垫，全员集结 | 每章都有推进；不得出现纯保温无推进的章节 |
| 101–120 章 | 最终决战，解决所有主线 | 爆点密集；控制卡的"不应包含"字段尤其重要——禁止在收官阶段引入未铺垫的新设定 |

### 定位校准规则

- 控制卡必须显式写出"本章位于全篇节拍地图的哪个区间"，以及"本区间的核心任务对本草的具体约束"。
- 若本章的节奏属性（钩子/蓄力/爆发/回报/转承）与所在区间的爆点密度要求明显不匹配（如在"每 3 章一个爆点"的区间连续安排"蓄力"章），必须在风险提示中标注并给出补偿方案。
- 若本章处于两个区间的交界处（如第 10 章与第 11 章之间），控制卡应同时考虑前后区间的约束，优先服从更紧迫的一方。

## 与其他 Skill / Prompt 的边界

- 本 Skill 是正文创作前的上游准备层。
- 本 Skill 不直接完成正文，也不负责终审评分。
- 连续性热度管理应由 `通用-管理连续性冷热线` 继续承接；两者可联动但不互相替代。
