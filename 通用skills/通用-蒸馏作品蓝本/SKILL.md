# 通用-蒸馏作品蓝本

> 核心理念借鉴自 [女娲 · Skill造人术](https://github.com/alchaincyf/nuwa-skill)：不是复制情节，而是**提取一部作品的叙事架构 DNA**——让下游写/审 Skill 能参照这套已验证的叙事规律，而不是凭空决定节奏和钩子。

## 继续读取的 references

- `references/作品蓝本模板格式定义.md`（**必读** — 产出格式规格与模板完整结构）

## 核心区别

| | 作者风格模板 | 作品蓝本模板 |
| --- | --- | --- |
| 蒸馏对象 | 一位作者的文笔特征（跨作品） | 一部作品的叙事架构特征（纵贯单作品） |
| 关注什么 | 句长、段落、感官、比喻、禁忌 | 章首切入方式、钩子轮换、回报间隔、节奏分布、信息释放节拍 |
| 产出用途 | 文笔约束（怎么写） | 结构参照（写什么节奏） |
| 关键区分 | 捕捉 HOW the author writes | 捕捉 HOW the story is structured |

| 维度 | 提取内容 | 下游消费 Skill |

## 执行流程

### Phase 0: 需求澄清

收到蒸馏请求后，确认：

1. **作品名**：确保理解正确
2. **章节范围**（必填）：蒸馏哪段范围？默认前 100 章或全本（若章节数 < 100）；用户可指定精确范围
3. **聚焦维度**（可选）：全部 8 维 vs 只聚焦节奏/钩子/回报等特定维度？
4. **平台标注**：该作品首发在哪个平台？（会影响节奏判断的基准线——番茄的"快节奏"和起点的"快节奏"不同）

用户说"蒸馏 XX 的蓝本"无更多信息 → 默认全 8 维 + 前 100 章（或全本）+ 网络搜索获取。

### Phase 0.5: 创建自包含蒸馏档案包

正式统计前，必须先在目标小说项目根目录创建或确认本轮蒸馏档案包：

```text
蒸馏产物/作品蓝本模板/[作品名]-作品蓝本档案/
	sources/                         # 用户提供或可公开读取的一手章节/目录/样章
	references/research/              # 本轮维度化采样记录，必须落盘
		01-章首模式指纹.md
		02-章末钩子指纹.md
		03-中段回报与高潮分布.md
		04-场景节奏与卷级节拍.md
		05-POV与对话密度.md
		06-信息释放与情感弧.md
	synthesis/                        # 规律归纳、冲突处理、样本置信度
	validation/                       # 质量验证记录
```

硬要求：

- 最终主模板仍写入 `蒸馏产物/作品蓝本模板/[作品名]-作品蓝本模板.md`，便于 `Agents.md` 注册和下游读取。
- 所有章节抽样、类型判定、钩子归类、回报间隔计算和冲突处理必须落入档案包；没有档案的蓝本不得标高置信。
- 若仅有目录而无正文，只能产出"目录级低置信蓝本"，不得伪装成正文级结构统计。
- 蓝本只提取叙事架构 DNA，禁止复制情节、人物关系、专属设定、专属意象或谜底设计。

### Phase 1: 信息采集

#### 采集优先级

**第一优先级（必须采集，统计级）**：
- **章首模式指纹**：逐章检查前 150-300 字的切入方式，分类统计
- **章末钩子指纹**：逐章检查章末 150-300 字的钩子类型，分类统计
- **中段回报指纹**：逐章识别中段回报类型和位置

**第二优先级（尽量采集，分布级）**：
- **场景节奏分布**：抽样 20-30 章判断紧张/松弛/爆发比例
- **POV 切换规律**：检查 POV 配置和切换频率
- **对话密度分布**：抽样统计对话占比

**第三优先级（补充采集，规律级）**：
- **信息释放节拍**：跟踪主要悬念/伏笔的设-埋-揭示时间线
- **情感弧分布**：抽样判断每章的情感入口→出口方向

#### 模式判断

| 模式 | 触发条件 | 策略 |
| --- | --- | --- |
| 网络搜索 | 用户未提供本地素材 | 通过在线阅读平台获取目录+正文片段+书评分析 |
| 本地语料优先 | 用户提供了全书 txt/电子书 | 先读本地，网络搜索补充外部分析 |
| 纯本地语料 | 用户明确说"只用我给的素材" | 只分析本地素材 |

#### 信息源

| 来源类型 | 揭示什么 | 优先级 |
| --- | --- | --- |
| 用户提供的全书文件 | 完整文本，最精准的统计基础 | 最高 |
| 作品目录/章节列表 | 确认总章数和结构 | 高 |
| 作品公开正文片段 | 可获取的章节样本 | 高 |
| 书评/拆解分析/读后感 | 外部对叙事节奏的定性判断 | 中 |
| 作者创作谈（如有） | 作者对结构的有意设计 | 中 |

信息源黑名单：知乎、微信公众号、百度百科。

#### 信息不足时的处理

| 情况 | 处理 |
| --- | --- |
| 只有目录无正文 | 只能基于目录做章节数量级估算，无法做内容级分析 |
| 只有少量章节样本 | 降低统计置信度，标注"样本量偏小" |
| 外部分析信息矛盾 | 以一手文本为准 |

### Phase 1.5: 采样 Review 检查点

完成章节采样后，先暂停输出一页采样质量摘要，确认是否继续提炼：

| 维度 | 样本范围 | 样本量 | 关键发现 | 风险 |
| --- | --- | --- | --- | --- |
| 章首模式 | 第 X–Y 章 | [N] 章 | [最高频切入方式] | [样本少/章节偏前/无] |
| 章末钩子 | 第 X–Y 章 | [N] 章 | [最高频钩子类型] | [无] |
| 回报/高潮 | 第 X–Y 章 | [N] 章 | [回报间隔] | [无] |
| POV/对话 | 第 X–Y 章 | [N] 章 | [POV规律/对话占比] | [无] |
| 信息/情感 | 第 X–Y 章 | [N] 章 | [悬念揭示节拍/情感弧] | [无] |

用户确认采样质量 OK → 进入 Phase 2。若样本偏窄，先补样本或在后续模板中明确降级为低置信。

### Phase 2: 统计与提炼

按 `references/作品蓝本模板格式定义.md` 的 10 个 section 逐项填充。

**统计原则**：
- 所有占比数据标注样本量（N=X）
- 钩子类型/回报类型的判别标准明确（如"信息曝光型钩子"的定义是：章末文字中出现了主角或读者之前不知道的关键信息）
- 轮换规律必须基于数据推导，不能凭感觉编
- "禁忌"类判断（该作品不做的事）需要明确标注依据

### Phase 2.5: 提炼确认检查点

提炼完成后，不立刻写最终模板，先输出结构摘要给用户确认：

- 蓝本核心结构指纹：3–5 条（必须是可执行节奏/钩子/回报规律）
- 量化字段：列出有明确样本量支撑的字段数量
- 低置信字段：列出只有目录、少量片段或二手评论支撑的字段
- 反复制边界：明确哪些内容绝不能被下游复刻（人物关系、设定机制、谜底、名场面）
- 与写作研究模板可能冲突的维度：例如平台通用要求更快节奏，但蓝本前期慢热

用户确认提炼方向 OK → 进入 Phase 3。若用户认为蓝本方向不对，回到 Phase 2 调整分类和归因。

### Phase 3: 产出与注册

1. 按模板格式生成完整的作品蓝本模板 `.md` 文件
2. 写入目标项目根目录下的 `蒸馏产物/作品蓝本模板/[作品名]-作品蓝本模板.md`
3. 在目标项目根目录的 `Agents.md` 中追加注册条目（若 `Agents.md` 不存在则创建）
4. 注册条目格式：

```markdown
### 作品蓝本模板
- 名称：[作品名]
- 路径：蒸馏产物/作品蓝本模板/[作品名]-作品蓝本模板.md
- 蒸馏日期：YYYY-MM-DD
- 蒸馏范围：[第 X 章-第 Y 章]
- 平台：[平台名]
```

5. 给用户提供蒸馏摘要：提取了哪些关键规律、8 个维度的置信度评估。

### Phase 4: 质量验证

最终模板写入前，必须做三项验证：

1. **留出章节回测**：选择未参与统计的章节，检查模板是否能解释其章首模式、章末钩子、回报类型和节奏位置。
2. **位置预测测试**：给出一个虚拟章位（如"第 12 章小高潮前一章"），用模板推导应采用的章首、回报和钩子配置，检查推导是否清晰可执行。
3. **反抄袭边界检查**：确认模板只描述结构规律，不复刻原作剧情、人物关系、设定系统、谜底或名场面排列。

通过标准：

| 检查项 | 通过标准 | 不通过信号 |
| --- | --- | --- |
| 回测解释力 | 留出章节主要结构现象能被模板解释 | 模板只写"节奏紧凑"这类空话 |
| 可生成性 | 能指导新项目的章首/回报/钩子选择 | 下游无法据此生成控制卡 |
| 反抄袭边界 | 没有原作情节链、专属设定、人物关系搬运 | 出现可识别原作结构复刻 |
| 诚实边界 | 标注样本范围、缺口和低置信字段 | 看似全能，无来源说明 |

验证结果必须写入档案包 `validation/`，并在最终模板中给出"置信度综合"。

### Phase 5: 双 Agent 精炼

验证通过后，默认启动两路独立精炼视角（可由主执行者模拟，也可由子 Agent 执行）：

- **Agent A：结构可执行性审阅**——检查蓝本字段能否直接服务 `设计分卷大纲 / 生成章节控制卡 / 强化章节开头 / 强化章末钩子`。
- **Agent B：原创边界审阅**——检查是否存在情节复刻、设定借壳、人物关系搬运、名场面复制风险。

主执行者综合两份意见，只接受能提升"可执行性 / 可审计性 / 原创边界"的改动；不为追求像原作而牺牲原创性。

### 更新已有作品蓝本模板

当用户说"更新某作品蓝本"、"加入后续章节"、"这个蓝本不准"时：

1. 先读取现有蓝本模板和档案包，确认样本范围、调研日期、章节覆盖和置信度。
2. 只对新增章节、新增卷段或用户指出的不准维度做增量采样。
3. 对比新旧结论：
	- 新样本强化旧规律 → 补来源与样本量
	- 新样本推翻旧规律 → 标注"阶段性节奏变化"，按卷段拆分规律
	- 新样本只在特定卷段成立 → 写成"卷段局部规律"，不得覆盖全书蓝本
4. 更新模板中的蒸馏日期、样本范围、置信度和版本说明，不重写无关字段。

## 与其他 Skill 的边界

- 本 Skill 蒸馏**单部作品的叙事架构特征**。
- `通用-蒸馏作者文风` 蒸馏**作者层面的文笔特征**（横跨该作者的多部作品）。
- `通用-分析竞对作品` 做**竞争层面的市场分析**（市场数据、内容创作、运营策略、受众反馈四层），与本 Skill 的叙事架构蒸馏是互补关系。
- `通用-设计分卷大纲` 和 `通用-生成章节控制卡` 消费本 Skill 产出，作为节奏和结构的参照蓝本。
