# 通用-章节创作闭环

章节创作闭环不是“写完正文就算完工”，而是一个带日志、回炉、评分门槛和读者产物的完整执行流程。

## 流氓启动法（强制心态）

**最核心的秘诀：先完成，再完美。破除三个常见幻觉：**

1. **"等灵感爆发"** — 真相是：小说是边写边长的，不是想出来的。
2. **"等大纲完整"** — 行动 → 反馈 → 迭代，而非"准备 → 准备 → 放弃"。
3. **"等文笔修炼到位"** — 90% 写不出小说的人，不是因为文笔不够，而是因为他们在等一个完美时机。

**策略就一句话：先开枪，再瞄准。** 

- 别等完美大纲、别追求开篇即封神、别死磕构思。
- 写着写着人物会活、情节会跑偏，这是正常现象。
- 与其花大半年构思和写大纲，不如先把初稿落地。
- **烂初稿也比空想强万倍**，而且是这些「不完美的初稿」推着你一步一步把想讲的故事落地生根。
- **现在就动笔，不要等。**

## 最小核心启动（强制）

- 若本轮写作仍处于“有意向但思路发散”状态，必须先产出一句“最小核心”：`谁在什么处境下，为了什么目标，正被什么阻力压迫`。
- 首章进入闭环前，必须明确“问题引擎”：读者看完第一章后，心里具体在追问什么。
- 闭环执行固定拆成 3 个独立动作：①先落稿；②再看反馈；③最后按反馈迭代。
- “继续准备”不是独立步骤；只要当前回合还没有实际落稿，就一律视为仍停留在第①步。
- 允许首轮粗糙，但不允许停在空想；日志里应记录本轮最小核心是否仍有效、问题引擎是否增强或偏移。

## 风格/蓝本/写作研究模板自动发现规则

若当前服务的项目根目录存在 `Agents.md`，启动章节创作闭环前必须：

1. 读取项目根目录的 `Agents.md`；若其中声明了 `主输出平台`，检索三类模板时优先匹配"适用平台"与主输出平台一致的模板，无匹配时回退到"适用平台：默认"的同类模板
2. 若 `Agents.md` 中注册了"写作研究模板"——读取对应路径的模板文件，将其作为本轮章节闭环的题材×平台默认门禁
3. 若 `Agents.md` 中注册了"作者风格模板"——读取对应路径的模板文件，将其作为正文创作、润色、去AI味和审阅阶段的统一文风基线
4. 若 `Agents.md` 中注册了"作品蓝本模板"——读取对应路径的模板文件，将其作为章首、回报、钩子、节奏和信息释放的闭环参照
5. 本 Skill 作为编排器主要负责读取、记录、传递三模板约束，并在日志中标注模板状态；具体字段由被调用的子 Skill 消费
6. 若项目根目录不存在 `Agents.md`，或其中未注册对应模板——回退通用默认模式，不报错，不阻断

## 主输出平台自动发现规则

若当前服务的项目根目录存在 `Agents.md` 且其中声明了 `主输出平台`，启动章节创作闭环前必须：

1. 读取项目根目录的 `Agents.md`
2. 按命名约定定位对应的 `通用-输出{平台名}版` Skill
3. 将平台 Skill 的门禁标准（字数门槛、开篇密度、回报间隔、钩子强度、标题规则）作为本章节闭环的默认门禁基线
4. 在日志中记录当前主输出平台及对应平台 Skill
5. 若未配置主平台或配置缺失——回退平台无关的通用默认模式，不报错，不阻断

本 Skill 作为编排器主要负责读取、记录、传递平台约束，并在日志中标注平台状态；具体平台规则由被调用的子 Skill（`通用-创建小说正文`、`通用-正文润色`、`通用-去AI味重写` 等）消费。

本 Skill 默认消费字段：

- 写作研究模板：章节门禁、章首约束、节奏间隔、禁忌类约束
- 作者风格模板：句长基线、段落节奏、对话风格配置、情绪表达方式、禁忌清单
- 作品蓝本模板：章首模式指纹、中段回报指纹、章末钩子指纹、场景节奏分布、信息释放节拍

## 默认模型温度参考（新增）

本 Skill 作为编排器不直接调用模型，但将以下温度约束传递给被调用的下游子 Skill 执行。温度是低成本、高回报的参数调整：审阅/审计类用较低温度保证判断稳定，创作类用中等偏高温度保证变化与新鲜度，修订/润色类居中。

| 步骤 / 子 Skill | 推荐温度 | 说明 |
|---|---|---|
| 通用-审阅章节正文（步骤 7/审阅轮） | 0.3 | 低创造性，保持判断稳定一致 |
| 通用-审阅章节正文（复审轮） | 0.3 | 同上 |
| 通用-正文润色（步骤 5） | 0.45 | 方向已定，适度约束 |
| 通用-去AI味重写（步骤 6） | 0.45 | 同上 |
| 通用-创建小说正文（步骤 4） | 0.58–0.70 | 需要创造性与变化 |
| 通用-强化章节开头 / 章末钩子（按需） | 0.45 | 局部强化，适度约束 |

## 何时使用

- 用户要求按 SOP 真实跑完整章或连续多章。
- 需要从大纲到终稿、再到审阅、读者笔记与分章书评的全链闭环。
- 需要支持断点恢复、批量模式、逐章门槛与最终摘要。

## 不适用情形

- 只写一章正文，不跑后续审阅与读者产物：优先使用 `通用-创建小说正文`。
- 只做审阅报告，不改稿：优先使用 `通用-审阅章节正文`。
- 只做某一步专项强化：优先使用对应专项 Skill。

## 常见触发词 / 用户说法速查

- 按 SOP 把这章跑完
- 从大纲一路做到终稿
- 这几章都按闭环来做
- 一直回炉到 9.2+
- 批量跑这几章
- 带日志续跑下去别停

## 默认组合调用顺序

1. 先认真仔细阅读本章实际出场人物对应的人物传记，以及与本章背景、技术、规则、证据、程序链、世界观有关的技术设定 / 背景设定 / 控制卡 / 连续性台账，确认本章可写范围、不可越界红线与本轮必须兑现的约束。
2. `通用-管理连续性冷热线`
3. `通用-生成章节控制卡`
4. `通用-创建小说正文`（默认按“骨架稿 → 分场景扩写 → 拼合检查”执行）
5. `通用-正文润色`
6. `通用-去AI味重写`
7. `通用-审阅章节正文`
8. `通用-强化章节开头` / `通用-强化章末钩子`（按需）
9. 写后回到 `通用-管理连续性冷热线` 更新动态状态、悬念 / 伏笔状态与回归压力；若发生关键结构偏移，再补决策记录
10. 读者侧产物生成

## 规划—写作—审查—归档闭环补强（新增）

- 上游规划不是可选前戏：`通用-管理连续性冷热线` 与 `通用-生成章节控制卡` 默认属于闭环启动条件；若本章唯一职责、承重 beat、情感弧或钩子链仍发虚，不宜直接进入正文。
- 控制卡若已显性判 `Red`，默认先回炉再写；`Yellow` 可以谨慎推进，但必须把缺口写进日志，不能假装成熟度已经达标。
- 审阅环节默认不仅给分，还要区分 `writer / polisher` 处理方，并标问题来源层：`[骨架层] / [扩展层] / [表达层]`；否则闭环会把结构问题误丢给句子层修补。
- 真正的闭环不止“正文 + 审阅 + 去味”三件套，还包含定稿后的连续性 / 归档更新：人物动态状态、章节摘要、悬念 / 伏笔状态、必要的决策记录与最小进度快照。
- 每轮闭环日志最好至少能回答：当前处理章节、当前步骤、是否阻塞、最近完成章节、待处理问题、下步 `1–3` 个动作。
- 连续性与归档默认只记已发生事实，不预测未来章节；若定稿章节与旧资料冲突，以定稿章节为准更新，并在日志里写明修正原因。

## 闭环启动前的裁判源复核（强制）

- 闭环开始前，以及任一章进入润色、去 AI 味、审阅回炉前，必须认真仔细阅读与该章实际出场人物对应的人物传记，以及与该章背景、技术、规则、证据、程序链、世界观有关的技术设定文档。
- 不得只看章节标题、章纲摘要、控制卡摘录、上一章印象或题材惯性就开写、开改、开审；凡涉及人物动机、能力边界、关系状态、设定代价、证据机制的判断，都必须回到作者侧裁判源核对。
- 若同一人物传记或技术设定存在多个版本，必须先确认当前可执行的最新版本；若关键裁判源缺失，必须先补齐、定位或明确阻断，不能靠常识补完后继续闭环。
- 每章日志、终审结论或回炉记录里，至少要写清“本轮核对了哪些人物传记 / 技术设定、哪些约束已兑现、哪些仍待补丁”，避免闭环日志只有抽象进度。
- 任何环节一旦改动触碰人物动机、能力边界、关系状态、规则代价或背景事实，必须先做裁判源复核，再继续后续步骤。

## 默认输出口径

- 默认按完整 SOP 跑到摘要收口，而不是停在正文或单轮审阅。
- 默认同时落盘正文、终审报告、读者产物与日志状态。
- 若进入 `通用-去AI味重写`，默认要记录本轮采用的手术强度与主要病灶，避免回炉记录只写“已去味”。

## 章级节拍护栏

- 默认每章至少跑出一轮：**钩子 → 冲突 → 中段回报 → 新的未解决风险**，不能只做到“有事发生”。这里的“新的未解决风险”是指：本章结尾必须留下一个会抬高主角代价、并明确推动下一章接棒的新增压力点。
- 连续 3–5 章最好形成一个可感知的小单元闭环，哪怕只是阶段性小胜、小识破或小翻盘。
- 若故事存在事实链 / 程序链 / 资源链等双轨推进，日志必须分别记录本章各自推进了什么，避免只剩单线热闹。
- “问题解决”不能直接抹平压力；本章解决一个具体问题后，默认还要带出一个更难的新问题、新代价或新窗口。

## 研究回灌补强（2026）

- 闭环执行默认加一条快审链：`30秒（首屏）→ 3分钟（前三章）→ 首卷/前3万字`，任一层断裂都要回炉而非带病推进。
- 若连续多章推进，默认每 `3-5` 章应至少形成一次阶段性小高潮或关键兑现，避免“章章有事、章章不结”。
- 中期疲软预警：若连续若干章只做信息搬运、情绪平铺或重复冲突，必须插入“情绪加油站”（反差、短回报、关系新位）再续跑。
- 闭环评分除文句顺滑外，必须同时核验：开篇抓力、人物代价、章中回报、章末驱动、手机端可读性。

## 题材竞对分析接入要求（强制）

- 若当前任务服务某个题材，且该题材目录下的 `竞对分析/` 已存在与当前项目、当前平台或当前赛道相关的竞对分析报告，闭环开始前必须先读取并纳入本轮目标。
- 不得把这些报告只当成背景资料；必须在日志、终审结论或回炉判断中显式写出当前章节 / 当前批次相对竞对的领先点、持平点、落后点与补丁方向。
- 章节闭环的默认目标不是“文件齐了、分数过线”，而是推动当前作品在关键维度上**全方位超越竞争对手**；若看不出明确超越路径，不得把闭环误判为完成。

## 最低交付

- 有最新正文、同步更新的 `## 章节后记`、最新终审报告、读者笔记、分章书评与任务摘要。
- 有日志续跑状态、评分记录与回炉判断。
- 能说明本章或本批次是否真正闭环、是否仍需回写上游层级。

## 本层职责

- 统一承接章节 SOP 的步骤定义、默认路径推导、批量模式、日志机制、完成出口与回炉门槛。
- 统一承接“存在文件不等于步骤已执行”的校验口径。
- 统一承接逐章摘要与批量摘要模板。
- 统一承接步骤 0 初始化、工件命名、未分类兜底与连续性台账默认位置。
- 当章节创作出现卡顿、续跑失焦或返工过大时，先回到九部件与进度节奏层重建顺序，再继续正文链路，而不是盲目硬写。
- 在步骤 5–9.5 之间，统一判断这章是“真实闭环”还是“文件已齐但链路未闭”，并明确需要回写的上游层级。
- 若第 3 步去 AI 味只做了轻修但问题实为人物假、对话太顺或破局太机械，应明确标记需要升级到更高强度再回炉，不能把“做过去味”误判成“问题已解”。

## 工件命名规则（强制）

- 章节正文主文件默认不带日期；`## 作者有话说` 与 `## 章节后记` 仍附着在同一章节文件内，不单独创建带日期文件名。
- 分章终审报告与分章书评文件名必须带日期，日期格式固定为 `YYYY-MM-DD`。
- 多平台派生正文文件名默认不带日期，沿用平台目录与章节路径命名；日期只用于对应审阅报告与书评，不用于平台正文本体。

## 硬规则

- 只有当正文、终审报告、阅读笔记、分章书评、日志状态全部闭环时，才允许宣称完成。
- 本章相关人物传记、技术设定与背景设定统一视为“启动前裁判源”。
- 步骤 1–9.5 的任一写稿、润色、去味、审阅动作前，都必须先完成这组裁判源复核。
- 未完成裁判源复核时，一律视为闭环尚未真正启动，不得伪装成已进入执行阶段。
- 任一章节正文在步骤 2 之后发生改动，都必须立刻补做“基础复检包”，不得只凭旧报告或目测放行。
"基础复检包"固定包含 4 项：①正文重跑字数门禁（参数按以下优先级确定：项目 `Agents.md` 中主输出平台指定 → 主输出平台对应 `通用-输出*版/SKILL.md` 的"平台默认字数范围" → 通用回退值），用 `scripts/count-chapter.ps1`（参数取上述来源）；②若同文件含 `## 作者有话说`，再跑 `scripts/count-afterword.ps1`（参数取上述来源）；③正文快速扫读，确认修订版未混入"初稿+二稿"拼接式内容（LLM 修订时常追加而非替换；若正文存在同一场景的两种写法先后出现，视为拼接事故，必须回炉清掉旧版残余）；④同步刷新所有受影响的审阅链。
- 字数门禁的唯一依据，是 `count-chapter.ps1` 的 `BodyCJK / Meets3500 / WithinRange`；`Len` 仅作参考，不得被"去空白统计"或任何自定义字符数替代。
- 字数超范围时遵循"标记→判断"两步法，而非"超了就退回"：超出范围先标记，再由审阅判断是否合理（如高潮章偏长可视为合理，解析错误的偏长才需退回）。不得跳过判断步骤直接退回。
- 任一日志、终审报告、读者侧摘要若出现"正文字数：XXXX（去空白统计）"但未同时给出 `BodyCJK / Meets3500 / WithinRange`，一律视为闭环未完成。
- 任一章节正文在步骤 2 之后发生改动，都必须同步刷新同文件 `## 章节后记`，至少复核：本章定位、功能点落地核对、爽点登记、伏笔与回收、设定/程序呈现、人物发展、证据要素、钩子类型、数字纪律检查、偏离记录、后续铺垫、读者吸引点与优化建议。
- 步骤 1–5 之间，任一正文改动后都必须复检正文区块是否残留“这几章 / 前几章 / 前面几章 / 前面这几章 / 后几章 / 后面几章 / 后面这几章 / 上一章 / 下一章 / 本章 / 这章 / 后文会 / 我们会看到 / 读者会发现”等章节自指 / 连载导览腔；残留即视为闭环未完成，不得进入终审通过。
- “整章 / 这整章 / 这一整章”同样属于正文区块必须清掉的章节自指 / 作者讲评腔；残留即视为闭环未完成。
- 步骤 3 / 4 / 5 / 6 / 7 / 8 / 9 不得因为“已有文件”或“分数看起来不错”被跳过。
- `9.20+` 的唯一判定，以**连续两轮独立终审在保留两位小数后的综合评分均严格大于 9.20** 为准。完整流程为：**①首轮终审（对标审阅 Skill 独立执行）→ ②基于首轮审阅报告逐条精修 → ③追加一轮独立复审（重新执行完整审阅，而非只检查旧问题）→ ④两轮评分均 > 9.20 方可收口退出**。首次过线 ≠ 收口；首次 > 9.20 后，必须再基于该轮报告做一轮实际精修（非伪修、非仅通读），再追加一次完整独立复审，两轮均过线方算闭环完成。
- 命中本 Skill 时，必须坚持执行器身份，除硬性缺参外，不得把阶段汇报伪装成完成汇报。
- 每章日志必须记录主卖点保真状态，至少回答“本章怎样呈现 / 强化 / 维持卖点；若未显性呈现，下一章由谁接棒”。
- 每章日志还必须至少记录：章首抓手、中段回报、章末接棒点；若存在双轨推进，还要分别记录每条推进线新增了什么证据 / 动作 / 损失。
- 回炉判断不得只看文句顺滑度；若卖点在正文阶段变淡、变虚、变泛，也必须判为未闭环。

### 工件路径落地规禁（新增 — 防产物漂移到小说正文/）

**现象**：执行时经常把审阅报告、阅读笔记、书评等派生产物一股脑塞进 `小说正文/`，而不是写入各自规定的目录。

**根因**：Step 0 虽要求生成派生路径，但缺少强制校验；AI 在执行时默认 CHAPTER_FILE 在 `小说正文/` 下，推导 REVIEW_REPORT_FILE 等路径时沿用了同一基目录，且未在落盘前校验归属。

**三条硬规则：**

**① Step 0.5：工件路径映射表强制输出**

在生产任何工件之前（包括 CHAPTER_FILE 的正文），必须先输出一张完整的**"工件路径映射表"**，写明以下每项，并逐项校验：

| 工件 | 变量 | 必须归属的根目录 |
|---|---|---|
| 章节正文 | CHAPTER_FILE | `小说正文/` |
| 章节控制卡 | CONTROL_CARD_FILE | `写作控制卡/` |
| 终审报告 | REVIEW_REPORT_FILE | `审阅意见/` |
| 阅读笔记 | READER_NOTE_FILE | `阅读笔记/` |
| 分章书评 | BOOK_REVIEW_FILE | `书评/` |
| 连续性台账 | CONTINUITY_LEDGER_FILE | `SOP执行日志/撰写章节/连续章台账/` |
| SOP 步骤日志 | 日志 | `SOP执行日志/撰写章节/` |

输出格式示例：

```text
【工件路径映射表】
  CHAPTER_FILE         → 小说正文/第1部/第2卷/1.2.3 深夜来访.md          ✓ 归属正确
  CONTROL_CARD_FILE    → 写作控制卡/第1部/第2卷/控制卡_1.2.3章_2026-06-11.md  ✓ 归属正确
  REVIEW_REPORT_FILE   → 审阅意见/第1部/第2卷/章节审阅报告_第1部_第2卷_第3章_2026-06-11.md  ✓ 归属正确
  READER_NOTE_FILE     → 阅读笔记/第1部/第2卷/阅读笔记_1.2.3章_2026-06-11.md  ✓ 归属正确
  BOOK_REVIEW_FILE     → 书评/第1部/第2卷/1.2.3 深夜来访_书评_2026-06-11.md  ✓ 归属正确
  CONTINUITY_LEDGER_FILE → SOP执行日志/撰写章节/连续章台账/连续性台账_第1部_第2卷_2026-06-11.md  ✓ 归属正确
```

**校验规则**：REVIEW_REPORT_FILE 必须以 `审阅意见/` 开头，READER_NOTE_FILE 必须以 `阅读笔记/` 开头，BOOK_REVIEW_FILE 必须以 `书评/` 开头。**任何一项不满足，必须回退修正路径后再继续，不得跳过。**

**② Step 0.6：目录同步创建**

Step 0 不仅要创建 `CHAPTER_FILE` 的父目录，还必须同步创建以下所有目录（若不存在）：

- `写作控制卡/第X部/第Y卷/`（或 `写作控制卡/未分类/`）
- `审阅意见/第X部/第Y卷/`（或 `审阅意见/第X卷/`）
- `阅读笔记/第X部/第Y卷/`（或 `阅读笔记/未分类/`）
- `书评/第X部/第Y卷/`（或 `书评/未分类/`）
- `SOP执行日志/撰写章节/连续章台账/`

若因路径不完整（如无法推导第X部/第Y卷）导致无法创建派生目录，必须先在日志中补齐定位信息，不得静默跳过。

**③ 落盘前归属校验门禁（每次 create_file 前强制执行）**

每次调用 `create_file` 或等价写入操作前，都必须先做一次归属校验：

- 写入 CONTROL_CARD_FILE 前，检查目标路径是否以 `写作控制卡/` 开头。否 → 阻断，先修正再写入。
- 写入 REVIEW_REPORT_FILE 前，检查目标路径是否以 `审阅意见/` 开头。否 → 阻断，先修正再写入。
- 写入 READER_NOTE_FILE 前，检查目标路径是否以 `阅读笔记/` 开头。否 → 阻断，先修正再写入。
- 写入 BOOK_REVIEW_FILE 前，检查目标路径是否以 `书评/` 开头。否 → 阻断，先修正再写入。
- 写入日志前，检查目标路径是否以 `SOP执行日志/` 开头。否 → 阻断，先修正再写入。

此门禁为不可跳过的硬规则。**若发现某个派生产物仍要写入 `小说正文/`，必须立刻纠正其路径，不得以"反正文件放在这里也能用"为由跳过修正。**

### 循环收敛门禁（新增）

每章的回炉-审阅循环默认最多执行 3 轮。经验表明，超过 3 轮后模型开始过度修正原本没问题的地方，实际产出质量可能先升后降。若 3 轮仍未达标，应：

1. 暂停该轮循环，评估是否需更换模型、调整提示词口径或补充裁判源
2. 第 3 轮评分若反而低于第 2 轮，强制截停
3. 若连续两轮评分差异极小（如浮动不超过 0.15），判定进入高原期——说明当前方向已耗尽改善空间，继续循环只会浪费 token，也应强制截停
4. 不得单纯继续重复「改→审」循环
