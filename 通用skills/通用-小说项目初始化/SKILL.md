# 通用-小说项目初始化

这不是"随便想想写什么"的构思阶段，也不是"直接写个大纲开干"的跳跃式启动，更不是"用户已经知道什么套路最赚钱所以只需要填空"的半自动工具。

## 本 Skill 的唯一目标

在指定的**平台**和**题材**约束下，确定这样一部小说应当具备的完整要素清单——它就是"最能吸引读者、最能赚钱"的那个方案。

## 最核心最重要的产出物：Agents.md（强制产出）

本 Skill 最核心最重要的产出物是**小说项目根目录下的 `Agents.md` 文件**。这是**必须产出**的，不可跳过。

所有下游核心 Skill（`通用-创建小说正文`、`通用-章节创作闭环`、`通用-正文润色`、`通用-多平台输出编排` 等）通过自动发现项目根目录的 `Agents.md` 来获取**主输出平台**与**POV视角设置**，并按命名约定加载对应的 `通用-输出{平台名}版` Skill，合并执行平台特定规则。

如果 `Agents.md` 不存在或未正确注册主输出平台，整个写作管线将回退到"无平台特定规则"的通用默认模式——这意味着所有平台级适配决策（节奏要求、章节长度、情绪风格等）都不会自动生效。

> **因此，检查本 Skill 是否真正"完成"的唯一标准是：项目根目录下是否存在一份正确的 `Agents.md`。** 详见下方《创建项目配置文件 Agents.md》。

除 `Agents.md` 外，本 Skill 同时产出"项目初始化蓝皮书"作为详细决策依据文件——它包含完整的分析链、决策依据、竞对差距清单和要素清单，是所有下游设计 Skill 的策略输入源。

## 本 Skill 的默认立场

**用户不需要知道什么套路最火、什么组合最能打、什么情绪最赚钱。这就是本 Skill 存在的意义。**

本 Skill 从零开始做全部决策。决策依据不是用户的主观经验，而是工作区中已有的数据资产：

- `写作研究/` 目录下的题材趋势研究、平台生态研究、写作技法研究
- `竞对分析/` 目录下的竞对分析报告、横向对比矩阵、市场空白点总结
- 题材包装层的 `题材名-设计题材定位框架/references/` 中的题材裁判源文件
- 通用层的 `通用-输出{平台名}版` / `通用-分析竞对作品` 等 Skill 沉淀的平台规则

初始化流程的每一环节，都以这些数据资产为依据来**自主做出决策**，用户只需确认和微调，而不是从零拍脑袋。

## 执行规则（强制）

### 规则一：从零自主决策

本 Skill 从零开始。执行前不必假定用户了解目标平台的爆款特征、热门套路、情绪偏好。所有决策数据来自以下路径的自动扫描：

```text
扫描优先级（由高到低）：
1. 项目根目录下的 `竞对分析/`         ← 同赛道竞品分析，最直接的决策依据
2. 项目根目录下的 `写作研究/`         ← 题材×平台研究，约束校准依据
3. `通用skills/写作研究/`         ← 跨题材写作技法研究
4. 项目根目录下的 `.github/skills/题材名-分析竞对作品/references/`  ← 题材竞对分析补充维度
5. 项目根目录下的 `.github/skills/题材名-设计题材定位框架/references/` ← 题材裁判源
```

上述路径中只要存在与当前 `平台×题材` 组合匹配的研究报告或竞对分析，就必须将其作为该环节决策的核心依据。

### 规则二：单文件蓝皮书——深度版

所有产出物汇总为一个文件。但"单文件"不等于"单薄"——每章必须包含完整的**分析链**，不是填空式清单。

```text
项目根目录/
└── 项目初始化/
    └── 项目初始化蓝皮书.md    ← 唯一的产出物，预计 15–30 页等效篇幅
```

蓝皮书每章的结构固定为以下**四段式**，缺一不可：

```text
## 第N章：章节标题

### ① 分析过程
- 基于哪些数据做出的判断（引用具体报告/竞对分析/研究文件）
- 推理链：从数据到结论的逻辑过程
- 对比了哪些替代方案

### ② 决策依据清单
- 支撑本决策的数据项（至少3条，标注来源文件）
- 每条依据的置信度（高/中/低）及理由

### ③ 最终决策
- 明确的结论，格式为"选择X，放弃Y，因为Z"
- 若涉及量化指标，给出具体数值

### ④ 对下游的输入
- 本决策如何被下游 Skill 消费
- 需要下游注意的约束条件
```

这种深度结构的理由：如果只告诉下游"主套路选A"，下游 Skill 不知道为什么选A，就无法在具体执行中保持方向一致。**每章的分析链就是所有下游设计者的决策上下文。**

蓝皮书必须包含以下 **10 个章节**，每章按上述四段式执行：

| # | 章节 | 对应模块 | 内容深度要求 |
| --- | --- | --- | --- |
| 1 | 市场校准结论 | 模块一 | 平台选择推理（对比了哪些平台、为什么选这个）、题材细化数据（子类型的市场规模证据）、读者画像来源、竞争定位（TopN竞品在哪、空白在哪） |
| 2 | 商业逻辑锚定 | 模块二 | 变现路径选择理由（该平台竞品的实际变现数据）、付费点布局逻辑（竞品节奏参考）、IP潜力判断依据 |
| 3 | 读者情绪定位 | 模块三 | 读者圈层划分证据（来自读者研究/本章说分析）、核心情绪锚定的数据支撑、爽点曲线的竞品对标依据、7关漏斗竞品转化参考 |
| 4 | 元设定骨架 | 模块四 | 世界观选型依据（为什么选这个背景/时代）、力量体系/规则的设计逻辑（参考了哪些同类作品）、势力关系的冲突设计、人设的原型来源与差异化理由 |
| 5 | 套路组合方案 | 模块五 | 套路选择推理（对比了3-5种组合的竞品数据，为什么选这个组合）、反套路创新点的来源（市场空白证据） |
| 6 | 商业化埋点布局 | 模块六 | 付费埋点位置的竞品节拍参考、IP改编适配的类型判断依据 |
| 7 | 可行性校验结论 | 模块七 | 四道校验的逐项评分与证据、风险预警的量化评估（概率×影响） |
| 8 | **竞对差距清单** | 跨模块 | 每本竞品的五维差距分析+证据表；不是摘要，而是逐条对比的数据矩阵 |
| 9 | **最能吸引读者和最能赚钱的小说要素清单** | 汇总 | 本文件的最终产物——前面8章的分析链全部汇总为一套完整的要素清单（见下方《核心产出要素清单》规格） |
| 10 | 诚实边界 | 汇总 | 全文件所有不确定项的汇总表、置信度总评、信息缺口声明、反常识声明 |

> 第9章不是独立的"检查清单"，而是前面8章分析链的自然收敛——每条检查项都应该能在前面找到它的分析依据。

### 规则三：数据驱动优先

- 每条关键决策必须标注依据来源（如"据《竞对分析/XXX报告》中Top1样本的前门数据"）
- 无数据支撑的决策必须标注"基于行业通用经验，建议后续验证"
- 若 `竞对分析/` 中没有与当前 `平台×题材` 匹配的报告，则自动调用 `通用-分析竞对作品` 生成竞对差距清单后再继续

## 适用场景

- 准备在某平台写某题材的新项目，不知道什么套路最赚钱
- 已有模糊灵感但想验证"这个方向能不能打"
- 已有写作研究和竞对分析数据，但不知道如何将它们转化为具体的创作决策

## 不适用场景

- 纯粹为爱发电的随性写作
- 短篇/中篇创作
- 续写已有多卷的作品单卷

## 依赖 Skill

- `通用-分析竞对作品`：当 `竞对分析/` 无匹配数据时自动调用，生成竞对差距清单
- `通用-深度研究`：当 `写作研究/` 无匹配研究时自动调用
- `通用-设计题材定位框架`：当题材定位需要框架化输入时调用

## 核心命令

| 命令 | 说明 |
| --- | --- |
| `/init --platform <平台> --genre <题材>` | 完整初始化。从零开始，自动扫描竞对分析和写作研究数据，自主决策全部七维模块，产出蓝皮书 + 强制产出 `Agents.md` |
| `/init-quick --platform <平台> --genre <题材>` | 快速初始化，缩小数据扫描范围，适合已有较清晰方向的场景 |
| `/init-check` | 对已有项目做初始化回溯：检查 `Agents.md` 和蓝皮书第9章的要素清单在当前版本中是否仍然成立 |

## 核心产出要素清单（第9章规格）

蓝皮书的第9章是最终产物。它必须将前面8章的分析链汇总为一套完整的**小说要素清单**。这份清单回答一个核心问题：

> **在[平台]上写[题材]，最能吸引读者和最能赚钱的小说长什么样？**

与普通检查清单不同，本章的每条要素必须标注"依据来源"和"置信度"。它不是凭空列出来的需求列表，而是前面所有分析的结论。

这份要素清单就是大纲设计阶段的直接输入。下游 Skill（设计总大纲、设计分卷大纲、设计人物传记等）以此为基础展开具体创作。

**重要**：第9章不是独立的"填空式清单"。用户阅读时应能在前面1-8章中找到每条要素的分析依据。如果某条要素在前面的分析链中没有被讨论过，说明分析链有缺口——本 Skill 的执行不完整，需要回到对应模块补全分析。

## 核心理念与工作流程

> 以下各模块的执行流程与原版本一致。区别在于：每一环节的决策**不再依赖用户主观判断**，而是以前置扫描的竞对分析和写作研究数据为唯一依据。

## 第一层级：刚性约束层

> 这是项目的"不可动摇线"，任何后续设定都必须无条件符合本层级的规则。先锚定"生存条件→变现路径→情绪靶心"，再谈具体创作。

## 模块一：平台适配性校准 —— 确认生存条件

选定平台和题材之后，首先要校准内容与平台的"基因"是否匹配。平台风格差异是刚性约束，不可能通过后期调整来弥补。

### 1.1 平台底层风格校准

行业内通常将主流平台的风格划分为四种类型。必须先让你的内容风格精准匹配目标平台的核心风格。

| 风格类型 | 代表平台 | 核心特征 | 叙事要求 |
| --- | --- | --- | --- |
| **无线风** | 七猫 | 爽感为第一创作逻辑，碎片化场景阅读 | 节奏快于起点、慢于飞卢；冲突密集；对慢铺垫容忍度极低 |
| **起点风** | 起点中文网 | 长期付费连载，读者接受慢节奏铺垫 | 剧情逻辑扎实、世界观完整、人物成长弧光清晰 |
| **新媒体风** | 番茄小说 | 短平快爽，情绪强度高 | 几百字就要出反转；强情绪、强代入感 |
| **飞卢风** | 飞卢 | 高频爽点，节奏极紧凑 | 开篇即高潮；冲突密度极高；主角爽感至上 |

**判断方法**：
- 精读目标平台的**官方作者攻略**（七猫写作指南、起点过稿秘诀等）
- 分析站内**大热榜/新书崛起榜**头部作品的内容特征
- 将风格要求拆解为：叙事节奏、冲突强度、情绪表达幅度等可落地指标

**核心原则**：平台风格没有高低优劣之分，只有适配性差异。在无线风平台写起点风故事，或在起点平台写无线风内容，失败概率极高。

### 1.2 平台商业化规则适配

平台的商业化模式直接决定了"钱从哪里来""读者为什么愿意付费"，也间接限定了内容的生产方向。

**模式A：免费广告分成模式**（七猫、番茄等）

- 收益逻辑：读者免费阅读 → 阅读流量/广告点击 → 作者分成
- 对内容的要求：**提升读者阅读粘性**——读者阅读章节越多、停留时长越长，收益越高
- 内容设计侧重点：强情绪、强代入感、高留存率；不要在前期设置付费门槛
- 签约模式示例（七猫）：保底+超保底分成、纯分成、超级纯分成，千字稿酬20-1000元不等
- 关键指标：读者连续阅读时长、广告有效点击率（取决于内容留存率）

**模式B：付费订阅+IP分成模式**（起点、晋江等）

- 收益逻辑：读者按章节购买 → 电子订阅分成 → 后续IP改编授权
- 对内容的要求：**支撑超长篇幅的叙事能力**——世界观、人物关系、核心梗必须能延伸
- 内容设计侧重点：付费钩子密度、剧情的可持续性、IP改编潜力
- 签约模式示例（起点）：电子订阅分成比例70%，但要求全版权绑定5年
- 关键指标：读者付费转化率、章节付费率、IP改编授权收入

**确认要点**：
- 目标平台的主流变现模式属于哪一类？（有时同一平台也有多种模式）
- 核心变现路径（选1-2种）：广告分成 / 付费订阅 / 短剧改编 / 版权输出 / 粉丝经济
- 变现逻辑如何转化为内容设计的刚性要求？

### 1.3 平台题材红线确认

每个平台都有明确的题材接收清单和负面红线。必须逐项确认：

- 📋 该平台是否接收目标题材？（如七猫男频不接收同人、文娱题材）
- 🚫 核心剧情、世界观是否触碰平台审核红线？（暴力/色情/封建迷信等）
- ⚠️ 目标题材在平台上是"热门→竞争激烈"还是"冷门→差异化空间"？
- ✅ 目标平台是否有该题材的扶持政策或征文活动？

**信息获取途径**：平台官方投稿指南、站内头部作品题材类型分析、编辑公开分享。

### 产出物

`项目初始化/项目初始化蓝皮书.md` 第1章「市场校准结论」，含：主平台确认、题材细化、读者画像、竞争定位。所有数据来源显式标注。

## 模块二：商业逻辑锚定 —— 确认变现路径

在确定平台的刚性约束后，将"要赚钱"的模糊目标拆解为可落地的商业指标，再反向推导内容的设计方向。**大纲不是剧情流水账，而是项目的商业计划书。**

### 2.1 确定核心变现路径

根据目标平台的底层收益逻辑，选择1-2种核心变现路径，其余作为辅助：

| 变现路径 | 收益来源 | 对内容的核心要求 | 典型平台 |
| --- | --- | --- | --- |
| **广告分成** | 读者阅读量+广告点击 | 高留存率、长阅读时长 | 七猫、番茄 |
| **付费订阅** | 读者按章节付费 | 付费钩子密度、价值感 | 起点、晋江、纵横 |
| **短剧改编** | IP授权费用 | 快节奏、强冲突、情绪密集 | 番茄、七猫 |
| **版权输出** | 海外/渠道分发 | 普适性题材、跨文化可读 | 起点、晋江 |
| **粉丝经济** | 周边/同人/社群 | 人设记忆点、情感代入深度 | 晋江、起点 |

**选择逻辑**：
- 免费平台（七猫/番茄）→ 核心靠广告分成，内容设计以"延长阅读时长"为第一目标
- 付费平台（起点/晋江）→ 核心靠付费订阅，内容设计以"支撑长期付费意愿"为第一目标
- 若兼顾短剧改编 → 在设定阶段就加入适配短剧节奏的元素

### 2.2 设计核心付费点（付费平台必做）

读者的付费行为不是突然发生的——它是通过持续释放情绪价值，不断强化阅读期待，在关键节点集中释放的结果。

**付费点类型**：

| 类型 | 触发机制 | 适合位置 | 设计要点 |
| --- | --- | --- | --- |
| **情绪引爆型** | 读者对主角的共情达到峰值 | 前期-中部（付费意愿最强烈的区间） | 冲突升至即将爆发临界点，制造"必须知道后续"的期待 |
| **真相揭示型** | 读者对故事真相的探索欲 | 中后段（付费意愿易下滑的区间） | 呼之欲出的核心秘密，在关键信息点上刻意中断 |

**设计要点**：
- 起点读者通常在10-15万字后产生首次付费行为
- 七猫等免费平台的付费触发节点通常延后到30-50万字
- 在大纲中提前标注每个付费点的位置、核心逻辑、情绪爆发方式

### 2.3 规划IP衍生潜力点（可选，增值项）

如果核心变现路径包含IP衍生改编，在初始化阶段就预埋适配改建设计：

- **叙事节奏适配**：开篇快速抛出核心矛盾；后续间隔一定章节安排小高潮
- **人物关系适配**：设计有明确情感/利益张力的冲突关系（契约婚姻、伪装身份、对立立场）
- **设定视觉化**：优先选择视觉化表达难度低的场景和世界观规则
- **短剧适配**：在剧情设计中加入"打脸逆袭""情感拉扯"等短剧用户偏好的经典叙事元素
- **长期IP预留**：在主线外设计可延伸的外传方向；在世界观中预留可深度开发的区域

### 产出物

`项目初始化/项目初始化蓝皮书.md` 第2章「商业逻辑锚定」，含：变现路径选择、付费点布局规划、IP衍生潜力点。

- 商业锚定结果 → 调用 `通用-平台签约评估框架` 做更精确的过稿评估
- IP潜力点 → 输入给 `通用-设计总大纲` 做长线剧情布局

## 模块三：读者情绪定位 —— 确认情绪靶心

商业价值的核心支撑是读者的情绪留存。如果说平台规则和商业目标是刚性约束，那**读者情绪就是整个项目的核心指挥棒**。

### 3.1 精准划分读者圈层

不同平台的读者群体，对情绪价值的需求截然不同。先锚定目标读者属于哪个圈层：

| 圈层 | 核心阅读需求 | 对内容的要求 | 典型平台 |
| --- | --- | --- | --- |
| **硬核爽文爱好者** | 释放压力，获取直接爽感 | 节奏快、冲突密、爽点密集、主角成长干脆利落 | 七猫、番茄、飞卢 |
| **深度内容参与者** | 沉浸感、剧情推理、伴角色成长 | 世界观严密、伏笔呼应、成长线清晰、行为动机合理 | 起点、晋江 |
| **泛休闲阅读小白** | 情绪直接、关系简单、记忆点易传播 | 开篇即核心矛盾、不绕弯、一句话可说清核心看点 | 短剧/短视频转化读者 |

**判断依据**：目标平台的用户画像 + 所选题材受众特征 → 从三类中选择一类作为核心受众。

### 3.2 锚定题材核心情绪

每个经过市场验证的题材都有其核心情绪点。初始化阶段必须精准锚定。

| 题材 | 核心情绪 | 情绪承载方式 | 付费平台侧重 | 免费平台侧重 |
| --- | --- | --- | --- | --- |
| **科幻** | 对未知世界的探索欲 | 真实可信的技术/文明设定 | 技术细节的合理性与迭代逻辑 | 脑洞冲突带来的打脸爽感 |
| **悬疑** | 对真相揭晓的期待感 | 环环相扣的未知恐惧 | 逻辑严密的解谜过程 | 氛围渲染+主角身陷迷局的紧张感 |
| **职场** | 对阶层突破的代偿满足 | 行业生态的真实细节 | 商战/行业竞争的真实博弈 | 扮猪吃虎+一雪前耻的爽感 |
| **爱情** | 对亲密关系的情感代入 | 符合预期的相处细节 | 循序渐进的真实情感成长 | 高甜或强虐的情绪拉扯 |
| **修仙/玄幻** | 对超脱现实的成长征服 | 清晰的升级体系+世界观 | 力量体系的逻辑自洽 | 快速升级+打脸轮回 |

**跨题材叠加**：纯单一题材已很难支撑长线剧情。核心题材保留作为"情绪基底"，叠加其他题材的热门叙事元素作为辅助——如"科幻+悬疑"用硬核科幻设定包裹悬疑解谜过程。

### 3.3 设计读者情绪爽点曲线

将抽象的核心情绪拆解为具体、可落地的爽点布局，贯穿整个故事。

**开篇阶段（前10章/约3万字）** ：极致密集

- 核心目标：抓牢读者，决定开篇留存
- 免费平台：前3秒无冲突 = 读者直接离开
- 付费平台：3万字内决定是否继续追读
- 第1章：建立代入感 + 抛出核心冲突/悬念 + 章末钩子
- 第2章：加深代入 + 展开冲突 + 给出一个小回报
- 第3章：确认主线方向 + 抛出更大悬念/冲突 + 章末钩子拉满

**发展期（10-50章/约3-15万字）** ：有节奏地持续释放

- 核心目标：提升留存率，将"流量用户"转化为"付费用户"
- 每3-5章一个小高潮/情绪点
- 每个小高潮结尾留钩子式悬念
- 让读者产生"欲罢不能"的追读感

**中后期（50章/15万字以后）** ：周期性引爆

- 核心目标：维持长期留存率和付费转化率
- 每10-20章一个大高潮，将前期积累的情绪价值集中引爆
- 每个大高潮后快速抛出下阶段冲突引子
- 确保情绪价值不会出现断层

**平台差异**：
- 免费平台：爽点布局密度更高，情绪间隔更短
- 付费平台：爽点布局密度可略降，但逻辑扎实度要求更高

### 3.4 读者决策漏斗预设

读者从第一眼看到书名到持续追读付费，经历7个心理决策关卡。每个关卡都需要初始化阶段预设策略：

| 关卡 | 读者决策 | 初始化预设内容 |
| --- | --- | --- |
| 1. 曝光层 | 看到书名封面→点不点开 | 书名策略、封面方向（参看 `通用-设计标题`） |
| 2. 简介层 | 看到简介→点不点开正文 | 简介核心钩子（参看 `通用-撰写内容简介`） |
| 3. 开头层 | 前300字→继不继续读 | 异常前置/冲突前置方案 |
| 4. 首章层 | 读完第1章→收不收藏 | 信息释放节奏、情绪波设计 |
| 5. 养肥层 | 前10章→追不追读 | 回报率规划、中段钩子分布 |
| 6. 付费层 | 上架章节→值不值付费 | 第1付费点设计、价值感预埋 |
| 7. 长期层 | 50万字后→弃不弃书 | 中段防崩策略、新冲突导入机制 |

### 产出物

`项目初始化/项目初始化蓝皮书.md` 第3章「读者情绪定位」，含：读者圈层定义、题材核心情绪、情绪爽点曲线、决策漏斗预设。

## 模块四：元设定体系化构建 —— 叙事骨架搭建

元设定是支撑整个故事运行的底层叙事基础，包括世界观、力量体系、势力关系和核心人物。这是所有后续剧情展开的核心依托，必须无条件适配前面三个维度的所有刚性约束。

### 核心原则

| 原则 | 说明 |
| --- | --- |
| **服务核心情绪** | 所有设定都必须以放大题材核心情绪为唯一目标。不能强化核心情绪的设定，再巧妙也应舍弃 |
| **低理解成本** | 优先使用读者已熟悉的现实元素或经典设定，降低读者的理解成本 |
| **逻辑自洽** | 所有规则、限制、成长路径必须前后一致（这一原则由 `通用-设计故事设定` 执行细化和校验） |
| **冲突承载** | 设定本身要能成为冲突的支点，而非仅仅为主角提供功能 |

### 4.1 世界观设定

世界观是故事发生的基础背景。**世界观设定的关键不是"完整严密"，而是"恰到好处的精简适配"**。

**执行步骤**：

**步骤1：时代/背景定位**

- 完全架空 / 半架空 / 真实时代背景
- 古代 / 现代 / 近未来 / 远未来
- 单一舞台 / 多舞台（如现实+副本/主世界+其他世界）
- 对新人作者最友好的类型：**现实背景下的局部异质化世界观**——在读者熟悉的环境中加入少量异质设定

**步骤2：核心矛盾设定**

世界层面存在什么根本矛盾？（决定了故事的主线和终局走向）

- 资源争夺（修仙资源/能源/土地）
- 权力斗争（王朝更迭/势力对抗）
- 生存危机（末世/灾难/外敌）
- 社会不公（阶级固化/制度问题）
- 真相遮蔽（阴谋/秘密/隐藏的真相）

**步骤3：底层规则**

- 物理法则是否与真实世界一致？
- 社会的核心运行逻辑是什么（实力至上/金钱至上/血统至上/知识至上）？
- 读者需要什么程度的信息量才能理解世界运行？

### 4.2 核心力量/规则体系设定

体系是支撑后续剧情展开的核心冲突支点。**核心要求：绝对逻辑自洽**。

**设计三原则**：

| 原则 | 说明 | 反面案例 |
| --- | --- | --- |
| **服务核心情绪** | 体系设计必须以放大核心情绪为目标 | 悬疑题材的力量体系与解谜无关 → 失效 |
| **有限制性** | 必须有清晰的边界和限制条件 | 无限制的能力 → 后期战力崩坏 |
| **冲突承载性** | 力量体系要天然具备支撑长期冲突的能力 | 力量体系与反派无关 → 冲突缺乏支撑 |

**金手指五维设计原则**（改编自《起点成神指南》）：

| 维度 | 核心问题 | 设计建议 |
| --- | --- | --- |
| 1. 助力升级 | 金手指是否帮助主角持续变强？ | 变强的过程要有节奏感 |
| 2. 推动剧情 | 金手指是否驱动主角主动行动？ | 被动触发依然需要主角的选择和努力 |
| 3. 适当包装 | 形式与市场偏好匹配吗？ | 系统流需创新包装，避免千篇一律 |
| 4. 限制条件 | 有合理的代价/限制吗？ | 无敌最无聊，限制创造戏剧张力 |
| 5. 成长空间 | 金手指本身能进化吗？ | 防止中期乏力，读者需要新期待 |

**金手指限制条件可选项**：

- 次数限制（一天只能用一次）
- 条件限制（需要特定条件触发）
- 代价限制（使用后虚弱/消耗寿命/代价递增）
- 成长限制（需要升级才能解锁更强功能）
- 暴露限制（被其他人知道会有严重后果）

### 4.3 势力关系设定

势力关系是故事的主要冲突来源。

**设计三原则**：

| 原则 | 具体要求 |
| --- | --- |
| **立场简化** | 阵营数量控制在3-5个，每个势力的核心目标让读者一眼可理解 |
| **冲突支撑** | 核心势力之间存在无法调和的利益分歧，确保冲突持续有来源 |
| **功能明确** | 每个势力在剧情中的功能（支撑/对立/中立）提前明确，不随意更改 |

**势力设计三分类**：

| 类型 | 功能 | 设计要求 |
| --- | --- | --- |
| 主角支撑势力 | 为成长提供资源/背书 | 与主角目标一致 |
| 主角对立势力 | 制造成长障碍 | 与主角目标对立，实力随主角成长递增 |
| 中立势力 | 关键平衡或信息反转 | 在核心利益上保持绝对中立 |

### 4.4 核心人物与人设卡设定

人物是读者情感代入的核心载体。"读者因人设而爱上作品，因剧情而留在作品里。"

**人物功能三层次**：

| 层次 | 角色 | 核心功能 |
| --- | --- | --- |
| 核心主体层 | 主角 | 读者情绪代入的唯一核心载体，推动剧情向终局发展 |
| 核心催化层 | 核心配角/CP | 与主角形成情绪互动、互补或张力，放大核心情绪效果 |
| 核心冲突层 | 对立配角 | 为主角成长提供明确目标逻辑，让情绪释放有合理支点 |

**人设卡标准化要素**：

| 要素 | 设计要求 |
| --- | --- |
| **基本信息** | 服务于核心功能，制造有记忆点的差异化特征 |
| **人物目标** | 明确、具体、有足够支撑性（不能是模糊的"追求强大"） |
| **人物缺陷** | 缺陷与能力形成有逻辑的冲突关系，让人物真实可感 |
| **核心能力/金手指** | 放大核心情绪、有明确限制、与剧情深度绑定 |

**人设反差**：在当前市场环境下，单纯的"强能力"人设已很难吸引读者。真正能戳中读者的是**人设反差**——人物的外在标签与内在真实特质的强烈对立。

### 4.5 元设定自检清单

- [ ] 世界观核心规则是否符合读者低理解成本原则？
- [ ] 力量体系的规则、限制、成长路径是否逻辑自洽？
- [ ] 势力之间的利益分歧是否足以支撑长期冲突？
- [ ] 主角的缺陷是否与能力形成合理冲突？
- [ ] 核心人物的目标是否明确、具体、有支撑性？
- [ ] 所有元设定是否都服务于题材核心情绪？

`项目初始化/项目初始化蓝皮书.md` 第4章「元设定骨架」，含：世界观设定卡、力量/规则体系、势力关系图谱、核心人设卡。

## 模块五：套路模组化适配 —— 将共性套路嵌入元设定

套路不是创作的敌人，而是经过市场验证的、最高效的叙事工具，是连接"元设定"与"读者情绪"的最短路径。本模块的核心方法是将流行套路以**模组化**方式，精准适配到已搭建好的元设定框架中。

### 5.1 正确理解"套路模组"

一个成熟的套路本质上由三个核心部分组成：

| 组件 | 含义 | 操作空间 |
| --- | --- | --- |
| **核心逻辑** | 套路不可更改的底层叙事支点 | ❌ 不可更改 |
| **经典冲突** | 市场验证中沉淀的情绪释放场景 | ⚠️ 可根据元设定灵活调整 |
| **适配边界** | 套路的适用条件与兼容约束 | 必须逐一检查 |

**工业化比喻**：元设定是主板，套路是标准功能组件。根据主板接口（平台/题材/商业约束），将最适配的套路模组精确插接在主板对应位置上。

### 5.2 五层套路体系与选择矩阵

| 层级 | 定义 | 决策时机 | 代表套路 |
| --- | --- | --- | --- |
| 叙事启动层 | 故事怎么开场 | 必选 | 重生、穿越、系统绑定、觉醒 |
| 核心冲突层 | 故事由什么驱动 | 必选 | 先婚后爱、废柴逆袭、复仇、解密 |
| 持续驱动层 | 长期吸引力怎么维持 | 方向性规划 | 升级打怪、种田经营、副本闯关 |
| 情感抓手层 | 读者情绪怎么牵引 | 题材决定 | 替身文学、破镜重圆、双向暗恋 |
| 反套路创新层 | 差异化竞争力在哪 | 必选 | 传统套路扭转、反常设定、融合创新 |

**题材×主套路推荐**：

| 题材 | 推荐主套路 |
| --- | --- |
| 都市悬疑 | 解密探案 + 成长升级 |
| 都市职场 | 商战博弈 / 行业揭秘 |
| 科幻 | 末日生存 / 探索发现 |
| 爱情（女频） | 先婚后爱 / 破镜重圆 / 暗恋成真 |
| 修仙/玄幻 | 废柴逆袭 / 苟道稳健 / 凡人修仙 |
| 系统/脑洞 | 系统任务 / 副本闯关 |

### 5.3 热门套路模组拆解

下面以最主流的三个套路为例，展示模组化拆解与适配方法：

**【先婚后爱模组】**

| 组件 | 内容 |
| --- | --- |
| **核心逻辑**（不可改） | 男女主因客观、无可抗拒的现实利益或道德约束，不得不结成名义上的契约婚姻。前1万字内明确传递给读者。 |
| **经典冲突**（可调整） | 签约阶段的利益博弈、同居生活的尴尬试探、外界质疑+被迫维护婚姻的合作默契、双向伪装下的暗流涌动 |
| **适配边界** | 需要足够情绪空间支撑关系慢慢成长；男女主的立场差异必须有足够的冲突性 |

**【马甲模组】**

| 组件 | 内容 |
| --- | --- |
| **核心逻辑**（不可改） | 主角出于明确目的长期隐藏真实身份，重要配角对主角的真实身份存在长期的根本性认知偏差 |
| **经典冲突**（可调整） | 身份差点暴露的惊险、认知偏差下的嘲讽和误解、隐忍布局、真相逐步曝光时相关角色的反转 |
| **适配边界** | 马甲身份与真实身份必须有足够差异点；隐藏身份的动机须充分 |

**【萌宝模组】**

| 组件 | 内容 |
| --- | --- |
| **核心逻辑**（不可改） | 萌宝是男女主之间的核心连接点，推动关系发展 |
| **经典冲突**（可调整） | 身份暴露危机、父母相认的关键助攻、保护萌宝免受伤害 |
| **适配边界** | 萌宝对主线必须不可替代；行为逻辑须合理 |

### 5.4 模组化适配四步骤

**步骤1：选择核心套路模组**

- 根据目标读者的情绪爽点需求，选择1-2个核心套路模组
- 优先考虑"模组与核心情绪的适配性""模组与元设定的基础兼容性"

**步骤2：用元设定元素替换通用元素**

- 将套路的核心冲突与元设定的核心支点进行深度绑定
- 示例：先婚后爱的"契约婚姻理由"→ 替换为世界观中的核心矛盾元素（如星际契约、商业联姻、权力制衡）

**步骤3：验证套路组合兼容性**

- 主套路+辅助套路是否存在逻辑冲突？（如苟道流+系统高调打脸=冲突）
- 套路组合能否支撑100万字以上的长线展开？
- 套路组合是否有清晰的"结束点"？

**步骤4：确定反套路创新点**

明确2-3个"预期违背"要素：

- 读者以为A会发生，实际是B发生
- 传统套路的某个环节被扭转
- 套路融合产生的新看点

### 产出物

`项目初始化/项目初始化蓝皮书.md` 第5章「套路组合方案」，含：主套路模组选择、模组化适配映射、反套路创新点。**注意**：套路选择不由用户决定——本 Skill 基于竞对差距清单和写作研究数据自主选择最优组合。

### 与下游 Skill 的关系

- 套路方案 → 输入给 `通用-设计总大纲` 做卷级节奏设计
- 套路方案 → 输入给 `通用-设计分卷大纲` 做卷内套路落地
- 套路方案 → 输入给 `通用-生成章节控制卡` 做章节级执行

## 模块六：商业化埋点布局 —— 预埋变现与IP支点

在完成套路模组适配后，将商业变现逻辑以**埋点**的方式嵌入核心设定和剧情节点。

### 6.1 付费转化埋点

| 埋点类型 | 布局方式 | 要求 |
| --- | --- | --- |
| 情绪引爆型 | 在冲突升至即将爆发的临界点中断 | 前中期每5-10万字设一个 |
| 真相揭示型 | 在核心伏笔呼之欲出时中断 | 中后期每10-15万字设一个 |
| 成长奖励型 | 在主角即将完成关键突破时中断 | 与升级节奏同步 |

### 6.2 IP改编埋点

| 维度 | 布局方式 |
| --- | --- |
| **视觉化适配** | 设定场景/能力时优先选择"一看就懂"的视觉形式，避免抽象难呈现的设定 |
| **短剧节奏适配** | 开篇快速释放强冲突；后续每3-5章安排逻辑完整的小高潮 |
| **人物关系张力适配** | 契约婚姻、伪装身份、对立立场等——短剧改编的核心卖点 |
| **长期IP预留** | 主线外设计可延伸的外传方向；世界观中预留可深度开发的区域 |

## 模块七：可行性校验 —— 项目能否落地

在正式动笔前，对项目进行全面的可行性校验。**这是项目立项前的最后一道关卡**。

### 7.1 合规定性校验

- [ ] 题材是否在目标平台的明确接收范围内？
- [ ] 所有设定是否触碰了平台的内容审核红线？
- [ ] 是否完全符合国家相关政策法规要求？

### 7.2 市场适配性校验

- [ ] 核心情绪、叙事风格是否与平台主流趋势一致？
- [ ] 核心情绪爽点是否与同题材头部作品保持在同一水平？
- [ ] 核心创新点是否与竞品形成明确差异化优势？

**建议**：通过此关后，将项目设定整理成精简创意说明，与目标平台编辑进行前置沟通。

### 7.3 商业潜力校验

- [ ] 同类题材作品在目标平台的留存率、付费转化率处于什么水平？
- [ ] 预估收益水平是否符合作者的预期？
- [ ] 现有商业化埋点能否支撑预估收益的实现？

### 7.4 叙事自洽性校验

用**长线剧情推演测试**校验以下维度：

- [ ] 世界观所有规则是否逻辑闭环？
- [ ] 力量/规则体系的成长路径是否逻辑闭环？
- [ ] 势力关系能否支撑从开篇到终局的冲突？
- [ ] 核心人物设定（目标/能力/缺陷）是否与剧情进展精准匹配？

### 7.5 风险预警清单

| 风险 | 严重度 | 概率 | 应对策略 |
| --- | --- | --- | --- |
| 平台政策变化 | 高 | 低 | 多平台适配预案 |
| 同类题材扎堆 | 中 | 中 | 强化差异化 |
| 中段写崩 | 高 | 中 | 预设套路转换机制 |
| 读者付费意愿低 | 高 | 低 | 付费点重设计 |
| 审核风险 | 高 | 低 | 提前规避红线内容 |

### 最终决策

- ✅ **通过**：进入大纲设计阶段
- ⚠️ **带条件通过**：列出待改进项，进入大纲后持续关注
- ❌ **不通过**：返回对应模块调整后再验证

## 模块八：创建项目配置文件 Agents.md（强制产出，核心产出）

> 这是本 Skill **唯一不可跳过的模块**。模块一至七的决策最终必须注册到项目根目录的 `Agents.md` 中，才能被下游 Skill 自动发现和使用。

项目初始化完成后，**必须**在小说项目根目录创建 `Agents.md`，注册**主输出平台**与**POV视角设置**。该文件被 `通用-创建小说正文`、`通用-章节创作闭环`、`通用-正文润色`、`通用-强化章末钩子`、`通用-多平台输出编排` 等核心 Skill 自动发现，作为平台特定规则合并执行的依据。

### Agents.md 格式要求

```markdown
## 主输出平台
起点中文网

## 主输出平台POV
叙事人称: 第三人称
语言: 中文简体
POV基线来源: 源稿
切换策略: 每卷需审批
```

### 字段说明

**主输出平台**（必填）：

- 填写目标平台名称，与 `通用-输出*版` Skill 名称后缀一致。例如：`起点中文网`、`番茄小说`、`七猫小说`、`晋江文学城`、`知乎盐选`、`豆瓣阅读`、`纵横中文网`、`出版社`、`微信订阅号`、`小红书`、`新浪微博`、`百度百家号`、`B站`、`WebNovel`、`My Fiction`、`GoodNovel`。
- 此设置被 `通用-创建小说正文` 等 Skill 自动发现，Skill 按命名约定加载对应的 `通用-输出{平台名}版` Skill 并合并执行平台特定规则。
- 若 `Agents.md` 不存在或未注册主输出平台，所有下游 Skill 回退平台无关的通用默认模式，不报错不阻断。

**主输出平台POV**（推荐填写）：

- `叙事人称`：主输出平台预期的叙事人称。可选值：`第一人称`、`第二人称`、`第三人称`。第三人称是绝大多数网文平台的默认值。
- `语言`：语言。`中文简体`、`中文繁体`、`英文`等。
- `POV基线来源`：POV 基线来源。固定值 `源稿`，表示以源稿正文的既有视角链路为准。
- `切换策略`：POV 切换策略。推荐值 `每卷需审批`（每卷切换需审批），或 `全书锁定`（全书锁定）。禁止在没有显式理由与日志审批的情况下在连载中途切换人称。

此 POV 设置被 `通用-多平台输出编排` Skill 读取，作为各平台 `platformPovContract` 的默认初始值。对于输出多个平台的项目，应在执行多平台输出前补充 `平台POV基线表`（见 `通用-多平台输出编排`）。

## 最终产出物

本 Skill 产出以下两类产出物：

### 产出物一：Agents.md（强制产出，核心产出）

- **路径**：`项目根目录/Agents.md`
- **性质**：**强制产出**。本 Skill 是否真正完成的唯一判断标准。
- **内容**：主输出平台注册 + POV 视角设置（详见上方《模块八：创建项目配置文件 Agents.md》）
- **消费方**：被 `通用-创建小说正文`、`通用-章节创作闭环`、`通用-正文润色`、`通用-多平台输出编排` 等核心 Skill 自动发现

> 若 `Agents.md` 未产出，本 Skill 视为未完成。所有下游 Skill 无法自动适配平台规则。

### 产出物二：项目初始化蓝皮书（详细决策依据）

所有模块的决策依据汇总为一个统一文件：**`项目初始化/项目初始化蓝皮书.md`**。

### 文件结构（强制）

```text
# 项目初始化蓝皮书

## 1. 市场校准结论（四段式：分析过程 → 决策依据清单 → 最终决策 → 对下游输入）
## 2. 商业逻辑锚定（四段式）
## 3. 读者情绪定位（四段式）
## 4. 元设定骨架（四段式）
## 5. 套路组合方案（四段式）
## 6. 商业化埋点布局（四段式）
## 7. 可行性校验结论（四段式）
## 8. 竞对差距清单（数据矩阵式，每本竞品一行，五维对比）
## 9. 最能吸引读者和最能赚钱的小说要素清单（核心产出，四段式输出结构，详见上文规格）
## 10. 诚实边界（所有不确定项的汇总表 + 置信度总评 + 信息缺口声明 + 反常识声明）
```

### 每章执行标准

- **① 分析过程**：不少于300字推理链。引用至少2个数据来源。对比至少1个被否决的替代方案。
- **② 决策依据清单**：列出3-5条关键依据，每条标注来源文件和置信度。
- **③ 最终决策**：一句话说清"选择了什么、放弃了什么、为什么"。
- **④ 对下游的输入**：明确本决策如何被下游 Skill 消费。
- **第9章例外**：按上文《核心产出要素清单》规定的表格/矩阵格式执行，不需要四段式（前8章的分析链已经是它的"分析过程"）。

### 三条红线

- ❌ **不允许多文件分散产出**。所有章节写入同一个文件。
- ❌ **不允许单章少于300字推理链**。纯列表无分析的章节视为未完成。
- ❌ **不允许决策无来源标注**。每条决策必须标注来自哪份报告、哪个竞品或哪项研究。

### 落盘位置

```text
# 强制产出（核心）
项目根目录/Agents.md

# 详细决策依据
项目根目录/项目初始化/项目初始化蓝皮书.md
```

**核心原则**：本 Skill 不做具体设计，而是为所有下游设计 Skill 提供**统一的决策输入源**。它回答"做什么、为什么做"；下游 Skill 回答"怎么做"。

---

## 不做什么

- 不做具体的总大纲设计（那是 `通用-设计总大纲` 的事）
- 不做详细的人物传记（那是 `通用-设计人物传记` 的事）
- 不做故事设定细节（那是 `通用-设计故事设定` 的事）
- 不做分卷拆分（那是 `通用-设计分卷大纲` 的事）
- 不做章节控制卡（那是 `通用-生成章节控制卡` 的事）
- 不做书名/简介的具体撰写（那是 `通用-设计标题` / `通用-撰写内容简介` 的事）
- 不做平台签约的精确评估（那是 `通用-平台签约评估框架` 的事）

所有上述 Skill 都应在项目初始化完成后、从初始化蓝皮书和 `Agents.md` 中获取输入，然后再启动各自的具体设计工作。

## 诚实边界

- 本 Skill 提供的套路模组化适配方法基于行业共性经验。不同平台和不同时间点的最佳实践可能变化，建议在具体执行时结合 `通用-深度研究` 获取最新市场情报。
- 平台用户画像数据（年龄/性别/付费习惯等）基于2025-2026年公开资料。网文市场变化较快，需持续更新。
- 读者情绪决策漏斗的"转化率"无公开数据支撑，各关卡设计以行业经验为参考，实际效果需在发布后通过数据验证。
- 商业化验证（模块7）不能替代 `通用-平台签约评估框架` 的正式评估，建议在投递前做一次完整签约评估。
- 本 Skill 假设你已经选定平台和题材。如果尚未选定，建议先使用 `通用-深度研究` 做题材趋势和平台生态研究。
- `Agents.md` 中注册的主输出平台决定了下游 Skill 自动加载哪一套平台规则。如果平台选择在项目中途发生变化，**必须更新 `Agents.md`** 并重新执行模块一（平台适配性校准），否则下游 Skill 仍按原平台规则执行。
- **反常识提醒**：初始化阶段最常见的陷阱是"追求完美"——花大量时间在元设定细节上却忽略了平台适配和情绪定位。建议三轮迭代：先用 `/init-quick` 跑通全流程建立整体认知，再用 `/init` 做精细化决策，最后用 `/init-audit` 补齐薄弱模块。
